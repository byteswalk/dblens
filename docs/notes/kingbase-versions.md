## MySQL、SQL Server 模式

两种模式的协议、系统目录和 PG 模式相同，双引号标识符、`LIMIT … OFFSET` 也能用，所以不另做方言，按原生（PG）规则处理。生成的 SQL 避开了这两种模式改变语义的写法：

| 写法 | MySQL 模式 | SQL Server 模式 | 改成 |
|---|---|---|---|
| `'a' \|\| 'b'` | 逻辑或，得到布尔值 | 没有这个运算符 | `OPERATOR(pg_catalog.\|\|)` |
| `::numeric` | `DECIMAL(10,0)`，截掉小数 | 同左 | `::pg_catalog.numeric` |
| `confkey[k.pos]` | 可用 | 方括号是标识符引号 | 按序号取的子查询 |
| `BEGIN` | 可用 | 语法错误 | `START TRANSACTION` |

另外：

- 日期时间、字符、二进制、GUID 是 `sys` 模式下的同名类型，OID 不同，驱动按类型名映射到标准类型。
- 自增列在系统目录里的 `attidentity` 是 `'i'`（MySQL 模式的 AUTO_INCREMENT）、`'q'`（SQL Server 模式的 IDENTITY），读表结构时算作自增。
- MySQL 模式把 numeric 显示成 `number`（如检查约束里的 `(0)::number`），迁移到其他 PG 系库时改回 `numeric`。
- MySQL 模式标为已适配；SQL Server 模式仍提示“尚未适配”，原因见下。

## 改了什么（其他）

- 保留字补上 V8R6 的 `AUTO_INCREMENT`、`CONNECT_BY_ISCYCLE`、`CONNECT_BY_ISLEAF`、`NVL`、`NVL2`、`SYS_CONNECT_BY_PATH`、`UROWID`，MySQL 模式的 `BEGIN`、`UNIX_TIMESTAMP`。

## 没解决：SQL Server 模式

- 不支持 `GENERATED BY DEFAULT AS IDENTITY`，自增列要写 `IDENTITY(1,1)`。设计器、迁移建自增列会失败。要改得给方言加 SQL Server 兼容模式。
- `time`、`datetime2` 按 100 纳秒计，和 MySQL 模式同名类型的格式不同，驱动只凭类型名分不开，读出的值不对。
- `bit`、`money`、`rowversion`、`sql_variant` 等类型原样显示。

## 测试

- V8R6、V9R1C10 的 oracle、pg 模式：工作区全量通过，包括和 PostgreSQL、达梦之间的双向迁移。
- V9R1C10 的 mysql 模式：按 pg 模式那一组测试全量通过。
- V9R1C10 的 sqlserver 模式：驱动一致性测试通过（去掉了上面读不对的类型）；服务层测试的夹具用 `GENERATED … AS IDENTITY` 建表，没有跑通。
- 回归：PostgreSQL 18、openGauss 7.0、MySQL 8.0、达梦全量通过。
