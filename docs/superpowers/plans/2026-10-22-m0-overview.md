# M0 地基：实施总览

**Spec:** `docs/superpowers/specs/2026-10-22-dblens-design.md`

M0 涉及驱动、方言、服务、接口和桌面外壳五个子系统，一份计划装不下。因此拆成 4 份按顺序执行的子计划。每份计划完成后，都能产出可以独立测试的软件。

后一份计划要写的代码依赖前一份的真实实现，所以只有 M0-1 现在写成了逐步可执行的详细计划。M0-2 到 M0-4 在前一份完成后再展开成详细计划，下面先列出它们的范围和任务清单。

## M0-2 达梦与 Oracle 驱动（任务清单）

1. **达梦 DPI 技术验证**：用 `libloading` 加载 `dmdpi`，跑通连接、执行查询、取行、取消、读取 LOB。结论写入 `docs/notes/dameng-dpi-spike.md`。
   - 这是一个**决策点**：如果不顺利，改用 ODBC（`odbc-api`）实现达梦驱动，后续任务相应调整。
2. **同步驱动工作线程框架**：在 `dblens-driver` 中实现 `BlockingWorker`，即"专用线程 + 命令通道"。对外提供异步的 `Connection` 包装，供达梦、Oracle 和以后的 JDBC 桥复用。
3. **原生库查找**：在 `dblens-driver` 中实现 `NativeLibLocator`。查找顺序是：设置中的路径 → 环境变量 → 平台常见安装位置。找不到时返回 `Error::DriverUnavailable { hint }`。
4. **达梦驱动** `dblens-driver-dameng`：连接、执行流、类型映射、取消、事务、LOB 预览。通过一致性测试；一致性测试针对虚拟机上的 DM8 服务器运行，达梦集成测试仅在本地运行（CI 中没有达梦镜像）。
5. **Oracle 驱动** `dblens-driver-oracle`：基于 `oracle` crate，在工作线程上实现执行流和类型映射；用 break 取消；执行后读取 DBMS_OUTPUT。通过一致性测试，测试库为 Oracle Free 容器。
6. **CI**：CI 只增加 Oracle 任务（gvenzl/oracle-free 服务容器 + 安装 Instant Client）；达梦仅在本地测试，CI 不包含。

## M0-3 方言层（任务清单）

M0-3 拆成两份子计划。M0-3a 是纯逻辑，已写成详细计划；M0-3b 要对着真实数据库调试元数据 SQL，并用到 M0-3a 的接口，等 M0-3a 完成后再展开。

**M0-3a 方言核心**（`2026-10-22-m0-3a-dialect-core.md`）
1. crate 骨架、兼容库变体识别（MySQL、MariaDB、TiDB、OceanBase、PG、金仓、openGauss、GaussDB、瀚高、Oracle、达梦）、标识符引用与占位符。
2. 语句拆分：处理字符串、注释、`$$`、`DELIMITER`、PL/SQL 块和 `/`，输出语句及其字节偏移。
3. 字面量生成与分页包装。
4. 原生类型与逻辑类型互转，配表驱动测试。
5. `Dialect` 结构体，以及由表模型生成 SELECT/INSERT/UPDATE/DELETE（M1 的"生成 SQL"菜单会用到）。

**M0-3b 元数据读取**（详细计划：`2026-10-24-m0-3b-metadata.md`）

前置事项（来自 M0-3a 终审，详见 `docs/notes/m0-3a-followups.md`）：`Dialect` 要带上服务器版本，元数据模板按版本分支；识别 PolarDB；对照真实服务器校验保留字表；在 DM8 上逐项验证 M0-3a 中尚未实测的达梦行为。

原则：方言层不做 IO，只负责"生成元数据查询（SQL 和绑定参数）"与"把查询结果行解析成结构模型"两件事，实际执行由 M0-4 的服务层负责。查询必须批量：一个 schema 的列、约束、索引各用一条 SQL 取回。参数一律绑定。

1. 模板加载：用 minijinja 按显式的 key 取模板。定义 `MetadataQuery { sql, params }` 和行解析的公共工具。
2. MySQL 元数据：schema 列表；表及注释；列；主键、唯一、外键、检查约束；索引；视图；触发器；过程和函数。组装成 `Schema`。附解析单元测试（用固定的行数据）和集成测试（真实的 MySQL 与 MariaDB）。
3. PostgreSQL 元数据，同时为金仓、openGauss 准备覆盖模板。手头没有这两种测试库，只做模板和单元测试，在文档里注明未经实测。
4. Oracle 元数据：基于 `ALL_*` 视图，包括同义词和 dblink；需要处理 `LONG` 类型的 `DATA_DEFAULT` 列，以及类型文本的拼装。
5. 达梦元数据：基于达梦兼容的 `ALL_*` 视图，注意达梦特有的系统表差异。集成测试用真实的 DM8 库。
6. 大 schema 的性能验证（每类对象一条 SQL）；用 insta 做元数据 SQL 的快照测试；同时处理 `docs/notes/m0-2-followups.md` 中归到元数据的事项（如没有使用的 `ConnectParams.database`）。

## M0-4 服务、接口与外壳（任务清单）

M0-4 拆成三份子计划：4a 服务层（第 1–4 项，详细计划 `2026-10-24-m0-4a-service.md`），4b 接口与服务器（第 5–7 项，另加 TLS），4c 前端外壳、桌面与打包（第 8–10 项）。原第 3 项中的"连接时可选 TLS"是驱动层的工作，移到 4b：各驱动目前都不支持（PG 用的是 `NoTls`），PG 用 rustls，MySQL 用 SslOpts，Oracle 用 TCPS 连接串，达梦需要调研；连接配置的 `options` 中加 `tls` 选项。

1. `dblens-service` 本地存储：SQLite 迁移；连接配置的增删改查（含环境标记和颜色）。
2. 密码存储：用 `keyring` 存系统钥匙串；钥匙串不可用时，用 Argon2 加 ChaCha20-Poly1305 加密后存本地，需要主密码。
3. 驱动注册表与"测试连接"：查询每个驱动的可用状态；连接时可选 TLS。
4. 会话管理：每个标签页一个会话，另有元数据连接池；`Policy` 接口和 `DefaultPolicy`；元数据缓存及其失效规则。（M0-4a 已完成；日志按天滚动放到 M0-4c 的应用入口）
5. `dblens-api` 的 REST 接口：连接配置、驱动状态、元数据浏览。中间件负责令牌和 Origin 校验。
6. `dblens-api` 的 WebSocket 执行协议：`exec`、`fetch_more`、`cancel`，以及 `result_start`、`rows`、`result_end`、`affected`、`message`、`error`、`done`。
7. `dblens-server`：可配置监听地址，启动时打印一次性令牌。
8. `web/` 最小外壳：Vite + React + TS + Ant Design；API 客户端；主题跟随系统；连接测试页（只用于联调，正式界面等 M1 的设计稿确认后再做）。
9. `dblens-desktop`：Tauri 2 外壳。
   - 进程内启动 api，向前端注入令牌。
   - 窗口：默认 1440×900 居中，屏幕小时取工作区 90%，最小 1024×640。
   - 置顶开关；记住窗口状态；"恢复默认窗口位置和大小"；窗口落在已不存在的显示器上时自动拉回。
10. 打包和更新：NSIS 按当前用户安装；Tauri updater 的密钥生成与备份说明；`latest.json` 的发布流程；CI 发布矩阵。

## 推迟到 M1 的设计细节

- LOB 的"整体获取句柄"：要依赖会话管理（M0-4）和 WebSocket 协议，在 M1 的结果集功能里实现。M0 的驱动只提供预览（`Value::Lob`）。
