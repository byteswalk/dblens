# M7a 数据库设计规范检查 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 规范库、条款和规则引擎、内置 3 份规范、检查结果和人工确认、HTML 报告：选规范、选对象、出报告的闭环。

**Architecture:** 新 crate `dblens-lint` 只做纯计算：输入结构模型和规范，输出条款结论。规范的默认值放在 YAML 数据文件里，用户改动在本地库只存差异。服务层取结构、起后台任务、保存 `lint_runs`，接口层加 `/api/lint/*`，前端加规范库和结果两种标签页。

**Tech Stack:** Rust（serde-saphyr、minijinja、rusqlite、insta）；React 19 + TypeScript、antd 6、TanStack Query、Vitest。

**Spec:** `docs/superpowers/specs/2026-10-30-m7-lint-design.md`

## Global Constraints

- 依赖只用正式发布版，跟随最新；新版发布满 7 天再升级。
- 前端给用户看的文字都用词条（中英文）；后端错误和提示用 `msg!` 词条（`src` 中的 `.rs` 不能有中文字面量，`#[cfg(test)]` 之后除外）；词条必须用字面量引用，没用到的词条会让测试失败。
- 内置条款的中英文写在 YAML 数据文件里，不带海关字样和样例。
- 代码注释用中文；文件 UTF-8、LF 换行；前端代码风格：无分号、单引号、两格缩进。
- cargo 命令加 `--config "source.mirror.registry='sparse+https://rsproxy.cn/index/'"`（clippy 写在 `clippy` 之后），并设 `CARGO_INCREMENTAL=0`；后端测试在 `DBLENS_LANG=en` 下运行。
- 实库测试一律串行（`--test-threads=1`），不加 `--include-ignored`。
- 前端工具用 PowerShell 执行（用 `pnpm exec`）。
- 测试数据库的密码只在命令行中以内联环境变量传入，不写进仓库、报告或提交信息。
- 界面保持现有布局和黑白基调，只用细微的强调色；交互用真实鼠标和截图验证。

## 与设计文档的差异（写计划时调整）

- 表数据量、低选择性这两条要查数据的规则，首期只挂规则、默认关闭，开启后报“无法判断”，查询能力放到 M7c。这样 M7a 不向数据库发额外查询。
- 模型文件只有表，没有视图、序列和存储过程：这些规则对模型报“无法判断”。
- 规则的说明和参数名放前端词条，后端只给规则编号和参数定义。

## 接口

```rust
// dblens-lint
pub struct Ruleset { pub id: String, pub name: String, pub builtin: bool, pub clauses: Vec<Clause> }
pub struct Clause { pub id: String, pub section: Section, pub text: String, pub enabled: bool,
                    pub severity: Severity, pub manual_note: Option<String>, pub rules: Vec<RuleRef> }
pub struct RuleRef { pub id: String, pub params: Map<String, Value>, pub databases: Vec<String> }
pub enum Verdict { Pass, Fail, Unknown, Manual, NotApplicable }
pub struct Issue { pub object: String, pub table: Option<String>, pub message: String, pub suggestion: Option<String> }
pub struct Review { pub verdict: Verdict, pub note: String }
pub struct ClauseResult { pub clause: String, pub verdict: Verdict, pub reason: Option<String>,
                          pub issues: Vec<Issue>, pub review: Option<Review> }
pub struct LintInput { pub schema: Schema, pub family: Family, pub objects_known: bool }
pub fn check(input: &LintInput, ruleset: &Ruleset, lang: Lang, on_clause: impl FnMut()) -> Vec<ClauseResult>;
pub fn rule_defs() -> Vec<RuleInfo>;
pub fn builtin_ids() -> &'static [&'static str];
pub fn builtin(id: &str, lang: Lang) -> Option<Ruleset>;
pub fn diff(base: &Ruleset, edited: &Ruleset) -> Overrides;
pub fn apply(base: Ruleset, overrides: &Overrides) -> Ruleset;
pub fn validate(ruleset: &Ruleset) -> Result<(), Error>;

// dblens-service
impl Store { lint_rulesets, lint_ruleset, create_lint_ruleset, update_lint_ruleset, delete_lint_ruleset,
             reset_lint_ruleset, save_lint_run, lint_run, lint_runs, delete_lint_run }
impl Service { start_lint(self: &Arc<Self>, req: LintRequest) -> Result<String>;
               review_lint_clause(..); lint_report(id, reviewer) -> Result<String> }
```
