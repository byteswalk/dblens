# M2a 表数据编辑 设计

日期：2026-10-26。上级设计：总设计文档 `docs/superpowers/specs/2026-10-22-dblens-design.md` 第 11 节（M2 数据："表数据网格编辑：改动暂存，生成的 DML 预览后在一个事务里提交。没有主键或唯一键的表只读"），以及 M1c2 设计文档第 5 节（数据标签，"M2 的编辑在它上面扩展"）。

M2 拆成两份（2026-10-26 与用户确认）：
- M2a 表数据编辑（本文）；
- M2b 导入：CSV / Excel 导入到表、SQL 文件导入，顺带加上对象树"导出整表"的入口。

## 1. 目标与范围

在数据标签中编辑表的数据：改单元格、新增行、复制行、删除行、从 Excel 粘贴。改动先暂存，提交前预览生成的 DML，在一个事务里执行。

不做：
- 查询标签的结果编辑；
- 视图、物化视图的编辑（数据标签打开视图时只读）；
- 大字段的完整编辑（超过预览长度的值只读）。

## 2. 已定的决策（2026-10-26 与用户确认）

| 问题 | 结论 |
|---|---|
| 编辑范围 | 只在数据标签：改单元格（可设为 NULL）、新增行、复制行、删除行（多选）、撤销单个改动或全部放弃；另支持从 Excel 粘贴 |
| WHERE 条件 | 主键（或唯一键）加上改动列的原值，能发现别人同时改过同一字段；NULL 用 `IS NULL`；浮点、长文本和大字段、JSON、二进制不参与比较（见 4 节）；删除只按主键 |
| 提交流程 | 先预览全部 DML（值写成字面量便于阅读，执行用参数绑定）；按钮为取消 / 复制到新查询标签 / 执行；在数据标签的会话里开事务逐条执行，全部成功才提交，失败整体回滚并标出失败的行；生产连接预览标红，不需要额外确认 |
| 粘贴 | 从选中单元格开始向右下覆盖；超出已加载行的部分新增行；按列类型解析，失败的格子标红，有标红时不能提交；空单元格对文本列为空字符串、其他类型为 NULL；多出的列忽略并提示 |

## 3. 行的标识与可编辑性

- 用主键标识行；没有主键时，用所有列都 NOT NULL 的唯一键（取第一个）；都没有时整张表只读，工具栏说明原因。
- 只读的列：生成列；二进制列；值是超过预览长度的大字段（`Value::Lob` 且 `truncated`）的单元格。
- 视图、物化视图的数据标签只读。

## 4. 改动集与 DML 生成（`dblens-dialect`，无 IO）

改动集（前端提交给后端，值用与结果集相同的 `Value` JSON）：

```json
{
  "schema": "public",
  "table": "orders",
  "changes": [
    { "kind": "update", "key": {"id": 1}, "original": {"price": "9.90"}, "values": {"price": "12.00"} },
    { "kind": "insert", "values": {"name": "新品", "price": "1.00"} },
    { "kind": "delete", "key": {"id": 7} }
  ]
}
```

（示例中值按 JSON 简写，实际为 `{"t": 类型, "v": 值}`。）

生成：每个改动一条语句，同时给出两种形式：
- 带占位符的 SQL 和参数，用于执行；
- 值写成字面量的 SQL，用于预览（复用 `Dialect::literal`）。

规则：
- **UPDATE**：`SET` 只含改动的列。`WHERE` 是行标识列 = 原值，加上改动列 = 原值：
  - 原值为 NULL 时写 `IS NULL`；
  - 不能可靠比较相等的列不参与：逻辑类型为 Float、Text（Oracle、达梦的 CLOB 不能用 `=` 比较）、Blob、Binary、VarBinary、Json、Other 的列；原值是大字段预览时也不参与。
- **DELETE**：`WHERE` 只有行标识列 = 原值。
- **INSERT**：只写给出的列；自增列和有默认值的列留空时不写；生成列不写。
- **顺序**：先删除，再修改，最后新增。这样"改掉主键再新增一行用回旧值"不会冲突。
- 占位符按方言：`?`（MySQL 系、达梦）、`$n`（PG 系）、`:n`（Oracle）。

## 5. 执行（`dblens-service`、`dblens-api`）

接口：
- `POST /api/profiles/{id}/changes/preview`：请求体为改动集，返回 `[{index, sql}]`（字面量形式），不执行。
- `POST /api/sessions/{id}/changes`：在会话中执行改动集，返回 `{applied}`；失败时返回错误，错误中带失败的改动序号 `index`。

执行：
1. 会话还在等待续取结果时，先停下并丢掉剩下的行（沿用 M1c2 的取消机制）。
2. 开事务：
   - 自动提交模式下临时关闭自动提交，结束后恢复；
   - 会话已经在手动事务中时（数据标签不会出现），返回 `invalid`。
3. 逐条执行：绑定参数；每条语句先经过 Policy；执行后读影响行数，必须恰好为 1。
   - 为 0：回滚，报"第 N 行已被修改或删除，请刷新后再改"（`conflict`，归入 `invalid` 类错误，附 `index`）；
   - 大于 1：回滚，报行标识不唯一；
   - 数据库报错：回滚，返回数据库的错误和 `index`。
4. 全部成功后提交。
5. 每条语句照常写入执行历史；回滚时，已执行的语句也记入历史，标为失败（错误为回滚原因）。

## 6. 前端（数据标签）

### 6.1 编辑状态

- 每个数据标签一份编辑状态（不随标签保存，关闭或刷新前确认放弃）：
  - 修改：行号 → 列 → 新值（原值取自已加载的行）；
  - 新增：追加在表格末尾的行；
  - 删除：行号集合。
- 显示：
  - 改过的单元格换背景色；新增行换背景色；删除行整行变灰并加删除线；
  - 解析失败的单元格标红，悬停显示原因。
- 改回原值的单元格自动取消改动；删除新增行就是直接移除。

### 6.2 操作

- 工具栏：新增行、复制行、删除行、撤销所选改动、全部放弃、提交（显示改动数）。
- 单元格编辑：
  - 用 Glide Data Grid 的编辑（双击或回车）；
  - 右键菜单：设为 NULL、撤销这个改动、复制、删除行。
- 粘贴（Ctrl+V，从 Excel 或其他表格复制的制表符分隔文本）：
  - 从选中的单元格开始，向右、向下覆盖；
  - 覆盖已有行算修改；超出已加载的最后一行时新增行；
  - 多出的列忽略并提示。

### 6.3 文本解析

按列的逻辑类型解析（编辑框输入和粘贴共用）：

| 逻辑类型 | 接受 |
|---|---|
| Bool | `true` / `false` / `1` / `0`（不区分大小写） |
| Int、UInt | 整数，检查位数范围 |
| Float、Decimal | 数字（Decimal 保留原文） |
| Date | `2026-10-26`、`2026/10/26` |
| Time | `13:45`、`13:45:30`、带小数秒 |
| Timestamp | 日期 + 空格或 `T` + 时间；带时区的类型接受 `+08:00` 等后缀 |
| Uuid | 标准格式 |
| Json | 合法的 JSON |
| 其他 | 原文 |

空单元格：文本类（Char、VarChar、Text）为空字符串，其他类型为 NULL。

### 6.4 提交

1. 点"提交"：向后端请求预览。
2. 预览对话框：
   - 列出全部语句，可以复制；
   - 生产连接时顶部标红提示；
   - 按钮为取消 / 复制到新查询标签 / 执行。
3. 执行：
   - 成功：清空编辑状态，按当前的过滤和排序重新读取；
   - 失败：保留编辑状态，按返回的 `index` 标出失败的行，显示原因。
4. 有未提交的改动时，刷新、改过滤或排序、关闭标签前先确认放弃。

## 7. 依赖

计划的第一个任务是依赖复查（`node scripts/check-deps.mjs`，本机需先设 `NODE_USE_ENV_PROXY=1`）。不引入新依赖：Glide Data Grid 自带单元格编辑和粘贴事件。

## 8. 测试

- **dialect 单元测试**：
  - UPDATE 的 WHERE：主键、改动列原值、NULL 原值、不参与比较的类型；
  - INSERT 省略自增和默认值列；
  - 语句顺序；
  - 各方言的占位符和预览字面量。
- **服务层和接口**（假驱动）：
  - 预览；
  - 执行成功并提交；
  - 中途失败回滚并返回 `index`；
  - 影响行数为 0 时报冲突；
  - 没有行标识的表被拒绝。
- **实库测试**（5 个库）：
  - 建带主键、唯一键、自增列、默认值的表，含中文和 NULL；
  - 一次提交同时包含新增、修改、删除，核对结果；
  - 另一个会话先改同一字段，再提交，触发冲突回滚，表中数据不变；
  - 没有主键的表被拒绝。
- **前端单元测试**：按类型解析；粘贴区域的计算（覆盖、新增、多余列）；编辑状态的合并（改回原值取消改动、删除新增行）。
- **浏览器实测**：5 个库，中英文界面；编辑、粘贴、预览、提交、冲突。
