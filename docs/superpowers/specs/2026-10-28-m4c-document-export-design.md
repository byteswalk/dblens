# M4c 文档导出 设计

日期：2026-10-28。上级设计：总设计文档 `docs/superpowers/specs/2026-10-22-dblens-design.md` 第 11 节（M4 模型："数据字典和设计文档导出（docx/html/markdown，可选模板）"）；M4a 设计 `docs/superpowers/specs/2026-10-27-m4a-model-compare-design.md`（模型目录、表文件、`/models` 接口、后台任务）；M4b 设计 `docs/superpowers/specs/2026-10-28-m4b-er-diagram-design.md`（ER 图、逻辑外键）。

## 1. 目标与范围

- 从模型或连接的 schema 导出两种文档：数据字典、设计文档。
- 格式：docx、html、markdown；数据字典另有 xlsx。
- 模板：html、markdown 用可编辑的模板文件；docx 可指定一个 .docx 作样式来源。
- 设计文档带 ER 图图片（默认图和选中的主题图），由前端按 M4b 的画法画好交给后端。

不做：
- PDF；
- 在 .docx 中写占位符和循环的 Word 模板；
- 例程、序列、同义词等表和视图以外的对象；
- 文档内容的手工编辑、增量更新。

## 2. 已定的决策（2026-10-28 与用户确认）

| 问题 | 结论 |
|---|---|
| 来源 | 模型和库的 schema 都能导出；库直接读结构，不必先另存为模型 |
| 文档种类 | 两种：数据字典（表清单和表明细）；设计文档（再加概述、ER 图、表间关系、视图） |
| 格式 | docx、html、markdown；xlsx 只用于数据字典 |
| 模板 | html、markdown 用 minijinja 模板文件，内置一套、可另存后修改；docx 由程序生成内容，可指定 .docx 作样式来源（类似 pandoc 的 reference-doc） |
| 方案 | 前端画 ER 图图片；后端（Rust）组织内容并写出四种格式，在后台任务中进行 |

## 3. 界面

### 3.1 入口

- 模型面板：模型节点、schema 节点的右键菜单"导出文档…"。
- 连接的对象树：schema 节点的右键菜单"导出文档…"。
- ER 图工具栏的"导出"菜单："导出设计文档…"，范围默认为当前这张图（默认图即整个 schema，主题图即图中的表和这张图）。

### 3.2 导出对话框

| 项 | 内容 |
|---|---|
| 文档种类 | 数据字典 / 设计文档 |
| 格式 | docx / html / markdown；数据字典另有 xlsx |
| 范围 | 模型：可多选 schema；只选一个 schema 时可勾选部分表（带名称过滤）。设计文档：勾选要放进文档的主题图（默认图总是放进） |
| 文档信息 | 标题、版本、作者、说明；默认取模型的名称和说明（库：库名） |
| 模板 | 内置，或选文件：html、markdown 选模板文件；docx 选样式来源 .docx；"另存内置模板…"把内置模板存一份出来修改 |
| 视图定义 | 设计文档、来源是库时：是否放进视图的定义（默认放） |
| 输出 | 桌面版：选保存位置；浏览器版：生成后下载 |

- 上一次的选项（文档种类、格式、模板路径、文档信息、视图定义）存在应用设置中，按来源（某个模型，或某个连接的某个库）分别记住。
- 开始后关闭对话框，任务列表中显示进度，可取消；完成后桌面版提示已写到哪里，浏览器版下载。

### 3.3 ER 图图片（设计文档）

- 前端在屏幕外挂一个不可交互的 React Flow，复用 M4b 的建图（`buildGraph`）、布局（`layout`）和表节点，逐张画成 PNG，画完卸载。
- 模型图用文件中保存的位置（缺位置的表按 M4b 的规则补排）；库的 schema 用自动布局。
- 显示方式：用图中保存的；库图按 M4b 的规则（表多时只显示表名）。
- 白底、浅色主题（同 M4b 的白底导出），2 倍像素；任一边超过 8000 像素时降为 1 倍；仍超过时改用"表名"显示方式重画，并在文档该图下注明"表较多，只显示表名；明细见各表"。
- 画图进度显示在对话框中，可取消；画完再开始后台任务。

## 4. 文档内容

后端先把结构整理成统一的文档内容 `DocContent`（可序列化），四种格式都从它写出，模板拿到的也是它。

### 4.1 数据字典

- 封面信息：标题、版本、作者、说明、生成时间、来源（模型名和目录，或连接名、库名）。
- 表清单：每个 schema 一组，列序号、表名、注释、列数；docx、html 中表名链接到明细。
- 每张表的明细：
  - 表名、注释；分区信息（有时）；
  - 列：序号、列名、类型、可空、默认值、标记（主键、自增、生成列）、注释；
  - 索引：名称、列（降序的列标出）、唯一、方法；
  - 约束：主键、唯一、检查；
  - 外键：名称、列、引用的表和列、删除规则、更新规则；
  - 逻辑外键：单独一组，注明"逻辑外键"；
  - 触发器：名称、时机、事件（不展开定义）；
  - 被引用：哪些表的外键、逻辑外键指向这张表；
  - 没有内容的组省略。
- 模型中读不出的表（文件有错）列在文末"无法读取的表"，附错误原因。

### 4.2 设计文档

在数据字典之上加（顺序：封面信息、概述、ER 图、表间关系、表清单、视图、表明细）：

- 概述：说明（模型的说明或对话框中填的），统计（schema 数、表数、列数、外键数、逻辑外键数）。
- ER 图：每个 schema 的默认图、选中的主题图，带图名和说明；图片的提示（见 3.3）。
- 表间关系：外键、逻辑外键的汇总表：从（表、列）、到（schema、表、列）、类别（外键 / 逻辑外键）、名称。
- 视图（来源是库时）：名称、注释、列；定义作为代码块（可关掉）。模型没有视图，不出这一节。

### 4.3 xlsx（数据字典）

- 工作表"表清单"：schema、表名、注释、列数；表名链接到"列"工作表中这张表的第一行。
- 工作表"列"：schema、表名、序号、列名、类型、可空、默认值、标记、注释；每行带 schema 和表名，便于筛选。
- 工作表"索引和约束"：schema、表名、类别（索引、主键、唯一、检查、外键、逻辑外键）、名称、列、引用、说明。
- 冻结表头、加筛选、自动列宽（按内容估算，有上限）。
- 单元格超过 32767 个字符时截断，在任务结果中提示。

## 5. 格式与模板

### 5.1 html、markdown 模板

- 内置四份模板（数据字典、设计文档 × html、markdown），编进程序。
- 模板引擎 minijinja（工作区已有依赖）：
  - 上下文是 `DocContent`；
  - 固定文字用 `t('键')` 按界面语言取（键和译文在 Rust 的消息目录中），内置模板中英文通用；
  - 不开放 `include`、`import` 读取其他文件（只有这一份模板）；
  - 过滤器：`md_cell`（markdown 单元格转义 `|`、换行）、`anchor`（生成锚点）等，模板中可用。
- 模板语法或运行出错：在开始任务前（语法）或任务中（运行）报出模板名、行号和原因。
- html：单个文件，内嵌样式（适合打印：分页时不拆表头），开头目录，表名互相链接；图片用 data URL 内嵌。
- markdown：GFM 表格；代码块放定义；图片存为 `<文件名>_images/<序号>-<图名>.png`，用相对路径引用。

### 5.2 docx

- 正文由程序生成 WordprocessingML（`quick-xml` 写），放进"样式来源"文档（`zip` 读写）：
  - 替换 `word/document.xml` 的正文，保留样式来源最后的节属性（纸张、页边距、页眉页脚的引用）；
  - 保留样式来源的 `styles.xml`、`numbering.xml`、主题、页眉页脚、`settings.xml`（加上打开时更新字段 `w:updateFields`）；
  - 图片加进 `word/media/`，补关系（`document.xml.rels`）和内容类型（`[Content_Types].xml`）。
- 内置样式来源：编进程序的一份 .docx，A4 纵向，中文正文"等线"，带标题 1–3、题注、表格样式。
- 样式按 Word 内部名（`w:name`，如 `Title`、`heading 1`、`Caption`、`Table Grid`）找样式编号，中文版 Word 做的样式来源也能用；样式来源中缺的样式补上内置的定义。
- 目录：开头插入目录字段（标题 1–2），打开时由 Word 更新页码。
- 表格：表头行跨页重复，列宽按比例；表名做书签，表清单中的表名链接到书签。
- 图片：按版心宽度（样式来源的纸张宽度减左右页边距）缩放，保持比例；过高时按版心高度缩放。
- 不能出现在 XML 中的控制字符去掉。
- 样式来源不是有效的 .docx（不是 zip、没有 `word/document.xml`）时，开始前报错。

### 5.3 xlsx

- 用工作区已有的 `rust_xlsxwriter`（同查询结果导出），内容见 4.3。
- 工作表名超过 31 个字符时截短（这里只有固定的三张工作表，不会出现）。

## 6. 服务层与接口

### 6.1 服务层（`dblens-service/src/document/`）

- `content.rs`：从模型（`ModelStore`，含逻辑外键、表文件错误）或库（元数据，含视图）组织 `DocContent`；按范围筛选 schema、表；算被引用、表间关系、统计。
- `template.rs`：内置模板、minijinja 环境（`t`、过滤器、禁止读文件）、渲染 html、markdown。
- `docx.rs`：样式来源的读取和校验、样式名查找、正文生成、打包。
- `xlsx.rs`：数据字典的 xlsx。
- `job.rs`：后台任务 `TaskKind::Document`（进度按已处理的表数，可取消），写到目标路径或任务目录；markdown 带图片时：桌面版写 `<文件名>_images/` 目录，浏览器版打包 .zip。
- 图片：用现有的上传（`POST /uploads`）存放，任务按上传编号取用；任务结束后照常清理。

### 6.2 接口

| 接口 | 说明 |
|---|---|
| `POST /documents` | 开始导出：来源（模型 id 或连接 id + schema）、范围、文档种类、格式、文档信息、模板路径、样式来源路径、视图定义开关、图片（上传编号、所属 schema、图名、说明、提示）、输出路径（桌面版）。返回任务 id。写到本机路径、读本机模板文件要求 `local_files` |
| `POST /documents/templates/export` | 把一份内置模板写到指定路径（要求 `local_files`） |
| `POST /documents/check` | 开始前检查：模板语法、样式来源是否有效、输出位置能否写；返回问题列表 |
| 任务接口 | 进度、取消沿用 `/tasks`；浏览器版的结果文件用任务的文件下载 |

### 6.3 前端（`web/src/features/document/`）

- `ExportDocDialog.tsx`：对话框（3.2），选项按来源记住。
- `render.ts`：屏幕外画 ER 图图片（3.3），逐张上传。
- 入口接到模型面板、对象树、ER 图工具栏。
- 中英文文案 `locales/*/document.json`。

## 7. 错误处理

- 开始前：模板语法错（行号）、样式来源无效、输出位置不能写、没有选中任何表。
- 任务中：读不出的模型表进"无法读取的表"并在结果中提示；读库出错时任务失败并给出原因；取消时删掉写了一半的文件。
- 格式限制：xlsx 单元格截断、控制字符去掉，都在结果中提示。

## 8. 测试

- service：
  - 从测试模型组织内容：复合外键、逻辑外键、被引用、跨 schema 引用、读不出的表、按范围筛选；
  - 内置 markdown、html 模板的输出快照（中英文各一）；
  - docx：解压后对 `document.xml` 快照；中文样式名的样式来源能找到样式；缺样式时补上；版心宽度计算；图片关系和内容类型；
  - xlsx：解压检查工作表名和若干单元格；
  - 模板出错报行号；模板不能读其他文件。
- api：没有 `local_files` 时禁止写本机路径；浏览器版的完整流程（上传图片、任务、下载）；markdown 带图片打包 zip。
- 实库：在模型实库测试中对各库的测试 schema 导出一次 markdown 数据字典，核对表、外键都在。
- 前端：对话框选项（种类与格式的联动、范围、记住选项）的单元测试。
- 浏览器实测：模型和库的四种格式导出、设计文档中的 ER 图、另存内置模板后修改再导出。
- 桌面手测（记入待测清单）：docx 在 Word 或 WPS 中打开、更新目录、套用自己的样式来源；保存对话框。
