# M5a 结构迁移 设计

日期：2026-10-28。上级设计：总设计文档 `docs/superpowers/specs/2026-10-22-dblens-design.md` 第 11 节（M5 迁移："选择源和目标 → 按逻辑类型映射结构，生成目标 DDL，可人工调整 → 分批迁移数据（断点续传、进度、行数校验） → 最后建索引和约束"）；
M3 设计 `docs/superpowers/specs/2026-10-27-m3-table-designer-design.md`（按方言生成 DDL）；M4a 设计 `docs/superpowers/specs/2026-10-27-m4a-model-compare-design.md`（比对、同步脚本的执行，跨家族留给 M5）。

## 1. 目标与范围

M5 拆成两份（2026-10-28 与用户确认）：
- **M5a 结构迁移**（本文）：把一个 schema 中的表和序列迁到另一个连接（可以是不同的数据库家族）的 schema；做完即可"只迁结构"。
- **M5b 数据迁移**（另行设计）：插在 M5a 的两步之间——建表 → 分批迁数据（断点续传、进度、行数和抽样校验）→ 建索引和约束；迁完把序列和自增推到当前值。

M5a 做：
- 任意库到任意库：MySQL 系（MySQL、MariaDB、TiDB、OceanBase MySQL 模式）、PG 系（PostgreSQL、openGauss、金仓 PG 模式）、Oracle 系（Oracle、金仓 Oracle 模式、openGauss A 模式）、达梦之间都能迁，经逻辑类型中转；
- 表（列、主键、索引、唯一约束、外键、检查约束、注释、默认值、自增）和序列；
- 映射表格调整（全局类型规则 + 逐列覆盖）和目标 DDL 预览；
- 目标已有同名表时逐表选择处理方式；
- 后台任务执行，迁移报告；只生成脚本另存。

不做：
- 视图、物化视图、存储过程、函数、触发器、同义词的转换：列进报告并附源库 DDL，由人工改写；
- 分区：只提示，按普通表迁；
- 字符集、排序规则：不迁，用目标库默认；
- 新建目标 schema 或用户（在 Oracle、达梦中等于建账号），目标 schema 必须已存在；
- 数据、序列和自增的当前值（M5b）。

## 2. 已定的决策（2026-10-28 与用户确认）

| 问题 | 结论 |
|---|---|
| 场景 | 任意库到任意库，经逻辑类型中转；实库测试重点覆盖信创替换的常见路线 |
| 对象 | 表 + 序列自动转换；视图、例程、触发器等列清单并附源库 DDL |
| 人工调整 | 映射表格（全局类型规则 + 逐表逐列覆盖），右侧只读的目标 DDL 预览；结构和数据（M5b）共用同一份映射 |
| 同名表 | 开始前检查出来，必须逐表（可批量）选择处理方式，默认停下 |
| 校验（M5b） | 行数必做，可选按主键抽样逐值比对 |
| 拆分 | M5a 结构、M5b 数据；数据用服务端流式分批（读源 → 按逻辑类型转换 → 参数化批量写入） |

## 3. 结构

### 3.1 方言层 `dblens-dialect::migrate`（纯逻辑，不做 IO）

输入：源方言、目标方言（含变体、兼容模式、版本）、源 schema 的表和序列、映射设置（`MigrationPlan` 中的选项、类型规则、覆盖）。
输出 `MigrationDraft`：
- 目标表和序列（`dblens_core::schema` 的结构，类型为目标原生类型）；
- 逐项提示 `MigrationNote { object, column?, level, message }`，`level` 为 等价 `Info` / 有损 `Lossy` / 不支持 `Unsupported`；
- 两步的 DDL：第一步建序列、建表（列、主键、注释）；第二步建索引、唯一约束、检查约束、外键（外键最后）。每条语句带所属对象，便于报告和出错时跳过。

建表、建索引和约束的语句复用 M3 的 DDL 生成（目标方言的 `table_create` 等），本模块只负责把源结构转换成目标结构。

### 3.2 服务层

- 读源 schema 结构（与文档导出、反向生成模型相同的读法），读目标 schema 中已有的表、序列、索引和约束名；
- 由 `MigrationPlan` 生成 `MigrationDraft`（供界面预览），开始前检查，生成执行脚本；
- 后台任务 `TaskKind::Migrate`：逐条执行，进度、出错记录、取消复用 M4a 同步的执行方式；
- 接口：`POST /migrations/draft`（读结构并生成草稿）、`POST /migrations/check`、`POST /migrations`（开始）、`POST /migrations/script`（只生成脚本）。

### 3.3 迁移方案 `MigrationPlan`（可序列化）

```text
source:  { profile, schema, tables: [..] | null（全部） }
target:  { profile, schema }
options: { name_case: keep | lower | upper, comments: bool, checks: bool }
type_rules: [ { source: "NUMBER(1)", target: "BOOLEAN" }, .. ]
overrides:  { 表名: { name?, skip?, columns: { 列名: { name?, type?, default?, expression?, skip? } } } }
existing:   { 表名: skip | recreate | missing_only }
```

方案可另存为 JSON 文件、再打开接着改；M5b 在其中加入数据选项和进度，作为断点续传文件。

## 4. 映射规则

### 4.1 类型

- 默认：源原生类型 →（`logical_type`）逻辑类型 →（`native_type`）目标原生类型，按目标上限钳制；
- 全局类型规则：按源类型名（可带参数，如 `NUMBER(1)`、`CLOB`）匹配，优先于默认；
- 逐列覆盖：直接填目标类型文本，按目标方言解析回逻辑类型校验，解析不了的给 `Lossy` 提示"不认识的目标类型"；
- `Lossy`：MySQL 目标的带时区时间戳、Oracle 目标的 TIME（存成文本）、无符号整数加宽、超长 VARCHAR 转成 TEXT/CLOB、精度或长度被钳制、JSON 转成文本类、时间间隔转成文本；
- `Unsupported`：逻辑类型为 `Other` 的类型（PG 数组、几何、MySQL ENUM/SET 等）默认按文本迁，必须逐列确认（覆盖或取消勾选，或在覆盖中确认按文本）才能开始。

### 4.2 名字

- 选项 `name_case`：保持 / 小写 / 大写，默认按目标：Oracle、达梦、金仓 Oracle 模式大写，PG 系小写，MySQL 系保持；
- 表、列、索引、约束、序列名都按选项转换，覆盖中的名字原样使用；
- 转换后重名、超过目标库的长度上限：报错（`Unsupported`），需在覆盖中改名；
- 保留字由目标方言照常加引号。

### 4.3 默认值

识别后换成目标写法：
- 字面量（数字、字符串、`NULL`）、布尔（`true/false` ↔ `1/0`，按目标类型）；
- 当前时间、日期：`CURRENT_TIMESTAMP`、`now()`、`SYSDATE`、`SYSTIMESTAMP`、`CURRENT_DATE`、`LOCALTIMESTAMP` 等；
- UUID 函数：`uuid()`、`gen_random_uuid()`、`sys_guid()`；
- 序列：`nextval('s')`、`s.NEXTVAL`，序列一并迁移时换成目标写法。

识别不了的不迁，给 `Lossy` 提示"默认值未转换"，可在覆盖中补填。

### 4.4 自增

- 目标写法：MySQL 系 `AUTO_INCREMENT`；PG、openGauss、金仓、Oracle 12c 及以上 `GENERATED BY DEFAULT AS IDENTITY`；达梦 `IDENTITY(1, 1)`；用 BY DEFAULT 以便 M5b 按原值写入；
- PG 的 serial（默认值为自有序列的 nextval）按自增处理，自有序列不再单独迁；
- 目标版本不支持标识列（如 Oracle 11g）时 `Unsupported`。

### 4.5 检查约束、生成列、表达式索引

- 同家族：表达式原样带过去；
- 跨家族：只有"简单表达式"（列名、字面量、比较、`AND/OR/NOT`、`IN`、`BETWEEN`、`IS [NOT] NULL`、括号）原样带过去，其余不迁并给 `Lossy` 提示，可在覆盖中手填表达式；
- 生成列迁不过去时改为普通列（M5b 照常迁数据），给 `Lossy` 提示；
- 选项 `checks` 关闭时不迁检查约束。

### 4.6 索引和外键

- 目标不支持的索引方法（GIN、HASH 等）去掉，`Lossy`；
- 目标不支持的外键动作（Oracle 的 `ON UPDATE`、`SET DEFAULT` 等）去掉，`Lossy`；
- 引用的表不在迁移范围内（也不在目标中）的外键不建，`Lossy`；
- MySQL 目标中长文本列上的索引需要前缀长度，`Lossy` 提示。

### 4.7 注释

选项 `comments` 打开时迁表注释和列注释（MySQL 写在建表语句中，其余用 `COMMENT ON`）。

## 5. 界面

### 5.1 入口

连接的对象树 schema 节点右键"迁移到…"，打开"迁移"标签页，源预填为该 schema。工具栏可"打开方案…"载入另存的方案。

### 5.2 标签页（自上而下三步）

1. **选择**：源连接、schema、表的勾选列表（默认全选）；目标连接、schema；选项（名字大小写、注释、检查约束）。"读取结构"读出源结构，并查出目标中的同名对象。
2. **映射**：左栏对象列表（表、序列），带提示图标，可只看有问题的；中间为选中表的列映射表格（源列、源类型、目标名、目标类型、默认值、提示），可改目标名、类型、默认值，可取消勾选某列；右栏为这张表的目标 DDL 预览（只读）。工具栏"类型规则…"管理全局规则。
3. **确认与执行**：同名表清单，逐表或批量选 跳过 / 删除重建 / 只建缺的索引和约束（M5b 再加 追加数据 / 清空后导入），不选完不能开始；`Unsupported` 的项必须先处理；汇总（几张表、几个序列、几条约束）；"另存脚本…"、"另存方案…"、"开始迁移"。目标为生产环境时，删除重建等危险语句走现有的确认流程。

执行中用任务进度通知显示两步的进度；完成后打开迁移报告：每个对象的结果、失败的语句和错误、未迁移的对象及其源库 DDL、全部提示；报告可另存为 markdown。

## 6. 执行与出错

- 开始前检查：目标 schema 存在；`Unsupported` 都已处理；同名对象都已选择；名字无冲突、不超长；目标版本支持所需特性。不通过不开始，指到具体的项。
- 第一步：建序列 → 建表（删除重建的先删）；第二步：建索引 → 唯一约束 → 检查约束 → 外键。
- 每条语句单独执行，不做整体事务（DDL 在 MySQL、Oracle 中隐式提交）。
- 某张表建失败：记下，继续其他表；第二步跳过这张表的约束以及引用它的外键。第二步的失败只记下。
- 取消在语句之间生效。
- 重试：修改映射后重新执行，已建的表选"跳过"或"只建缺的索引和约束"。

## 7. 测试

- 方言层单元测试：一份覆盖各种类型、默认值、自增、检查约束、外键、索引的源结构，对每对家族（MySQL / PG / Oracle / 达梦，及 openGauss、金仓、TiDB、OceanBase 变体）生成草稿和 DDL 做快照；默认值转换、简单表达式判断、名字大小写与冲突与超长、类型规则匹配各有测试。
- 服务层：假驱动测开始前检查、同名表处理、执行顺序、出错继续、生产环境确认、取消；接口测试。
- 实库（串行）：在 11 个库上各建一套测试结构，每个源迁到 MySQL、PG、Oracle、达梦，另加 Oracle → 金仓、openGauss，MySQL → TiDB、OceanBase；迁完读回目标结构，用 M4a 的同家族比对与草稿的目标结构对比应无差异；最后清理。
- 前端：映射表格编辑、提示过滤、方案的组成与另存、同名表选择的校验。
