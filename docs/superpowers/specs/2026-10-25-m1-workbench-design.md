**上位文档**：`docs/superpowers/specs/2026-10-22-dblens-design.md`，第 7 节。本文档细化其中的界面，并记录 2026-10-25 与用户逐项确认的决定。

## 1. 已确认的界面决定

| 项 | 决定 |
|---|---|
| 整体风格 | 紧凑的 IDE 风格（接近 DataGrip / VS Code）：信息密度高、细边框，面板可拖动调整大小 |
| 窗口顶部 | **自绘标题栏**：菜单、窗口置顶按钮、最小化 / 最大化 / 关闭合并在一行，标题居中 |
| 左侧导航 | **活动栏 + 侧栏**：图标栏切换"数据库 / 历史 / 收藏 / 运维查询"四个侧栏，底部是设置 |
| 连接组织 | 所有连接在一棵树里，可以同时展开多个；连接前用彩色圆点标出环境（开发绿、测试黄、生产红、未标记灰） |
| 编辑器标签页 | 每个标签页绑定一个连接和一个会话；标签顶部有一条环境色线；生产连接的标签整块标红，标题带"生产" |
| 结果面板 | 在编辑器下方，跟随各自的标签页；每个结果集一个标签，失败的语句单独一个标签，另有"消息"标签 |
| 连接对话框 | 左侧选数据库类型，右侧分"常规 / SSL/TLS / 高级"三个标签；Oracle、达梦缺客户端库时，直接在对话框里确认目录 |
| 生产确认 | 沿用 DefaultPolicy：只在生产连接上，对不带 WHERE 的 UPDATE/DELETE、DROP、TRUNCATE 弹确认框，显示语句和原因，按钮为"取消 / 仍然执行"。不要求输入库名 |
| 侧栏 | 历史（搜索、按连接或失败过滤）、收藏（文件夹）、运维查询（随当前连接的方言变化，kill 语句只生成不执行） |

**与上位文档的差异**：设计文档 7.1 节把"历史"放在下方的结果面板里。本设计把它移到左侧的历史侧栏，结果面板只放结果集和消息。改动理由：历史跨标签页、跨连接，放在跟随单个标签页的结果面板里不合适。

### 1.1 主窗口布局

从上到下依次是：

1. **标题栏**（32px）：图标、菜单（文件 / 编辑 / 查看 / SQL / 窗口 / 帮助）、居中标题（"当前标签 · 连接 — DBLens 数洞"）、置顶按钮、窗口按钮。
2. **主体**：
   - 活动栏（44px）；
   - 侧栏（默认 270px，可拖动，可折叠）；
   - 工作区：
     - 标签栏；
     - 编辑器工具栏：执行当前语句、执行全部、停止、出错停止 / 继续、连接和 schema 下拉框、事务模式、提交、回滚、格式化、执行计划、收藏；
     - 编辑器；
     - 可拖动的分隔线；
     - 结果面板。
3. **状态栏**（24px）：当前连接和服务器版本、事务状态、最近一次执行的行数和耗时、光标位置、方言、编码。

各分隔线的位置、侧栏宽度、打开的标签页都存进设置，下次启动时恢复。

### 1.2 平台差异

- **Windows / Linux**：完全自绘标题栏。
- **macOS**：保留系统的红黄绿按钮（左上），菜单在屏幕顶部的系统菜单栏；标题栏只放标题和置顶按钮。
- **浏览器模式**（`dblens-server`）：标题栏变为页面顶栏，只有菜单和标题，没有置顶和窗口按钮。

### 1.3 快捷键

|---|---|

## 2. 前端架构

- **库**（具体版本和选型理由见 2.1 节）：
  - Ant Design：控件、对话框；
  - Monaco：编辑器；
  - Glide Data Grid：结果表格，canvas 渲染；
  - `react-resizable-panels`：可拖动的面板；
  - Zustand：本地状态；
  - TanStack Query：服务端数据。
- **状态划分**：
  - 连接列表和对象树的数据交给 TanStack Query，负责缓存和刷新；
  - 打开的标签页、每个标签的会话、编辑器内容、结果集交给 Zustand，按功能分成几个 store；
  - 设置（主题、面板大小、打开的标签）也放在 Zustand，并同步到后端。
- **不用路由**：单窗口，靠标签页切换内容。
- **目录结构**：

  ```text
  web/src/
    app/        布局外壳：标题栏、活动栏、侧栏、工作区、状态栏
    features/   connections · tree · editor · results · history · favorites · ops · settings
    shared/     api（REST）· ws（执行协议）· theme · window（窗口与原生能力）
  ```

  M0-4c 的联调页在 M1a 中删除。`token.ts`、`api.ts`、`exec.ts` 移到 `shared/` 继续使用。
- **主题**：
  - 用 antd 的亮色 / 暗色算法，加一套 CSS 变量；
  - Monaco 和 Glide Data Grid 跟着切换；
  - 设置为"跟随系统 / 亮色 / 暗色"三选一，"跟随系统"时随系统主题实时切换。

### 2.1 开源选型：难点不从零实现

原则（用户 2026-10-25 要求）：有难度的底层逻辑，凡是有成熟稳定的开源项目，都用它或参考它的代码，不自己从零开始。下表版本取自 2026-10-25 的 npm 仓库，许可证都可用于本项目。

| 难点 | 选用 | 说明 |
|---|---|---|
| SQL 格式化 | `sql-formatter` 15.9（MIT） | 支持 mysql、mariadb、tidb、postgresql、plsql 等方言。DBLens 方言对应：MySQL 系用 mysql / mariadb / tidb，PG 系用 postgresql，Oracle 和达梦用 plsql |
| 编辑器 | `monaco-editor` 0.57 + `@monaco-editor/react` 4.7（MIT） | 设计文档指定 |
| 语法高亮、语法校验、上下文补全（MySQL 系、PG 系） | `monaco-sql-languages` 1.2 + `dt-sql-parser` 4.5（DTStack，MIT） | 基于 ANTLR4：词法高亮；语法错误标记；按光标位置给出该出现关键字还是库、表、列；收集语句中的表和别名（用于 `a.` 补全）。对象名称由我们按元数据缓存提供 |
| 同上（Oracle、达梦） | ANTLR 官方语法库 grammars-v4 的 PL/SQL 语法 + `antlr4ng` + `antlr4-c3` | dt-sql-parser 没有 Oracle。按 dt-sql-parser 的做法（它本身就基于 antlr4ng 和 antlr4-c3）生成 Oracle 解析器，达梦语法与 Oracle 兼容，共用一套。达梦特有语法遇到不兼容时再在语法上补。在 M1b 中先做技术验证，确认解析速度和补全效果 |
| 高亮兜底 | Monaco 自带的 sql / mysql / pgsql Monarch 规则 | 解析器加载前或解析失败时使用；PL/SQL 的 Monarch 规则以 Monaco 的 sql 规则为基础修改，不从零写 |
| 结果表格 | `@glideapps/glide-data-grid` 6.0（MIT） | canvas 渲染，10 万行流畅 |
| 可拖动面板 | `react-resizable-panels` 4.15（MIT） | |
| 状态管理、服务端数据 | `zustand` 5、`@tanstack/react-query` 5（MIT） | |
| 图标 | `@tabler/icons-react` 3.49（MIT） | 设计稿用的就是 Tabler，直接沿用 |
| 语句拆分、语句分析（后端） | 沿用 M0：`dblens-dialect` 的拆分；`sqlparser` 0.63 做语句分析 | 已有，已测试 |
| xlsx 导出（后端） | `rust_xlsxwriter`（MIT / Apache-2.0） | 设计文档指定 |

执行计划在实现前要再确认：
- 选定库的维护状态，看最近一年是否有发版；
- 体积和按需加载的方式，Monaco 和 ANTLR 解析器都要懒加载。

### 2.2 与 Tauri 的边界

M0 的原则是"前端只通过 HTTP 和 WebSocket 调用业务，不用 Tauri IPC"。业务调用继续遵守这一条。原生能力（设计文档 4.1 节）是例外，经 Tauri 调用：
- 自绘标题栏的窗口操作：最小化、最大化或还原、关闭、拖动、置顶切换；
- 系统文件对话框，用于导出时选择保存位置。

约束：
- 全部封装在 `shared/window` 中，其他代码不直接调用 Tauri；
- 浏览器模式下这些函数退化为空操作或网页下载；
- Tauri 权限只开放上面几项，作用范围只限 `http://127.0.0.1:*` 上的本地页面。

置顶菜单项和快捷键沿用 M0-4c 的实现，标题栏上的置顶按钮与之同步状态。

| **M1a 界面框架与连接** | 自绘标题栏与窗口控制；活动栏、侧栏、标签页、可拖动面板；主题与设置；连接对话框、密码库的初始化与解锁；对象树（懒加载、过滤、复制名称、刷新） | 管理连接、浏览对象，替代联调页 |

## 5. 错误处理

- **原则**（设计文档第 8 节）：不吞错误。接口错误对象按 `kind` 转成中文提示，沿用 `errorText`。
- **按场景展示**：
  - 连接、认证失败：显示在连接对话框或标签页顶部；
  - SQL 错误：显示在结果面板，并在编辑器中标红；
  - 协议错误：用全局通知。
- **会话断开**（`broken`）：标签页顶部出现提示条，提供"重新连接"，由用户确认后执行。
- **密码库已锁定**（`locked`）：任何需要密码的操作都先弹出解锁对话框，解锁后重试原操作。
