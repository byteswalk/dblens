# M2b 导入 设计

日期：2026-10-27。上级设计：总设计文档 `docs/superpowers/specs/2026-10-22-dblens-design.md` 第 11 节（M2 数据："CSV/Excel 导入：列映射、类型校验、分批提交、出错时跳过或停止。表或查询结果导出"）。M2 的第二份（M2a 表数据编辑已完成）。

## 1. 目标与范围

- CSV / Excel 导入到已有表，或按文件新建表后导入；
- 执行 SQL 文件（后台任务，支持几百 MB 的文件）；
- 对象树的"导出数据"入口（整张表或视图），复用 M1c3 的导出。

不做：
- 一次导出多张表或整库（属于 M5 迁移或以后的批量导出）；
- JSON、XML 等其他格式的导入；
- 导入时的数据转换表达式（如拼接列、函数）；
- 把 SQL 文件打开到查询标签（大文件不适用，小文件可直接复制粘贴）。

## 2. 已定的决策（2026-10-27 与用户确认）

| 问题 | 结论 |
|---|---|
| 目标表 | 已有表，也可以按文件新建表（推断列类型，建表前可改列名和类型，建表语句预览后执行） |
| 写入方式 | 追加；清空后导入（DELETE 与导入在同一事务）；按主键更新（存在则更新，不存在则插入） |
| 事务与出错 | 两种模式：整体一个事务（任何错误全部回滚）；分批提交（默认每批 1000 行），出错时停止或跳过（跳过时把出错的批逐行重试，失败的行写入出错报告）。清空后导入固定用整体一个事务 |
| SQL 文件 | 后台任务：另开连接，边读边拆分、逐条执行，显示进度、可取消，出错时停止或继续，可选整体一个事务；生产连接开始前二次确认 |
| 文件解析的位置 | 后端（方案 A）。浏览器模式先上传文件，桌面版直接读本地路径。前端只做预览、映射和选项 |

## 3. 入口与界面流程（前端）

### 3.1 入口

- 对象树，表的右键菜单："导入数据…"（目标为这张表）、"导出数据…"（第 7 节）；视图的右键菜单："导出数据…"。
- 对象树，库/schema 的右键菜单："导入到新表…"、"执行 SQL 文件…"。
- 对象树，连接的右键菜单："执行 SQL 文件…"（默认 schema 为连接的当前 schema）。
- 标题栏"文件"菜单："导入数据…"、"执行 SQL 文件…"：用对象树中选中的连接；没有连接时打开新建连接。
- 数据标签工具栏："导入"按钮，目标为当前表（视图和只读表不显示）。

### 3.2 导入向导（对话框，3 步）

1. **选文件**：
   - 支持 `.csv`、`.tsv`、`.txt`（按 CSV 处理）、`.xlsx`、`.xls`。
   - 桌面版用系统的打开对话框选本地文件；浏览器模式选文件后上传，显示上传进度。
   - CSV 选项：编码（自动 / UTF-8 / GBK）、分隔符（自动 / `,` / `;` / Tab / `|`）、首行是列名（默认是）。
   - Excel 选项：工作表（默认第一个）、首行是列名（默认是）。
   - 预览前 100 行；选项改变时重新预览。预览中提示列数不齐的行数。
2. **目标与列映射**：
   - 已有表：表格列出文件列 → 表列。按列名自动匹配（去掉首尾空白，不区分大小写），匹配不上的可手动选，也可选"不导入"。同一个表列不能被映射两次。用目标列的类型校验预览的 100 行，解析失败的单元格标红并提示原因（只是提示，不阻止下一步）。
   - 新建表：填表名（默认取文件名去掉扩展名，清理成合法标识符），schema 为入口所在的 schema。每列可改列名、类型（下拉为常用逻辑类型，带长度/精度）、可空，可勾选主键（可多列）。下方实时显示建表语句预览（后端生成）。
3. **写入选项**：
   - 写入方式：追加 / 清空后导入 / 按主键更新。新建表时只有追加。表没有主键，或主键列没有全部映射时，"按主键更新"不可选并说明原因。MySQL 系选"按主键更新"时提示：任何唯一键冲突都会走更新。
   - 事务：整体一个事务 / 分批提交（每批行数，默认 1000，范围 100–100000；出错时停止 / 跳过）。选清空后导入时固定为整体一个事务。
   - 空值：空单元格写 NULL（默认）/ 文本列写空字符串（非文本列仍写 NULL）。
   - "开始导入"：生产环境连接先弹确认，写明连接、表名、写入方式；选清空后导入时额外写明"将删除表中全部数据"。
   - 大文件提示：Excel 文件会整个读入内存，超大数据建议另存为 CSV。

### 3.3 进度与结果

- 沿用导出的通知样式（右下角，可以关闭对话框后继续在后台运行）：进行中显示已读行数、已写行数、跳过行数（CSV 另显示已读字节百分比），可取消。
- 完成后显示汇总：写入行数、跳过行数、用时、警告数。有跳过的行时提供"下载出错报告"；导入到新表或导入完成后刷新对象树中这个 schema 的表列表，并提供"打开数据"按钮（打开数据标签）。
- 失败（停止模式或整体事务出错）时显示出错的文件行号和原因，以及已提交到第几行（分批模式）。

### 3.4 执行 SQL 文件对话框

- 选项：文件（同 3.2 的取文件方式，扩展名 `.sql` 或任意）、编码（自动 / UTF-8 / GBK）、目标 schema（默认入口所在的或连接当前的）、出错时停止 / 继续、整体一个事务（勾选后固定为出错时停止）。
- 整体一个事务的提示：MySQL、Oracle、达梦的 DDL 会隐式提交，不能回滚；文件中不应再有自己的事务语句。
- 点"开始"后先扫描（第 6.2 节），需要确认时弹确认框，确认后执行。
- 进度：已读字节百分比、已执行语句数 / 总数、失败数、用时；可取消。
- 结束后列出前 100 条失败（行号、错误、语句开头），点一条可"在新查询标签中打开"这条语句；提供"下载执行日志"。

## 4. 文件的存放与解析（`dblens-service`）

### 4.1 存放

- 浏览器模式上传到数据目录的 `imports/` 下（文件名为随机 id 加原扩展名），返回文件 id。导入或执行任务结束（成功、失败、取消）后删除；服务启动时清空 `imports/`。上传后一直没有使用的文件，1 小时后清理（与导出的过期清理放在一起）。
- 桌面版传本地路径，后端只读，不复制、不删除。
- 后端接受的文件来源：`{ upload: id }` 或 `{ path: "..." }`。`path` 只在桌面模式下接受（浏览器模式拒绝，防止经网页读取服务器上的任意文件）。
- 上传大小上限：默认 2 GB，可在设置中修改。

### 4.2 CSV

- 用已有的 `csv` 库流式解析（RFC 4180 引号与转义）。
- 编码：用 `encoding_rs` 边读边转码。自动判断：有 BOM 按 BOM（UTF-8 / UTF-16）；否则读前 64 KB，能按 UTF-8 解码（末尾被截断的多字节字符不算错误）就用 UTF-8，否则用 GB18030（兼容 GBK）。转码出错的字节替换为 `�` 并计入警告。
- 分隔符自动判断：在前 20 行中（引号内的不算）统计各候选字符 `,`、`;`、Tab、`|` 每行的出现次数，取各行次数相同且最大的那个；都不满足时用 `,`。扩展名为 `.tsv` 时默认 Tab。
- 列数不齐：多出的列忽略，缺少的列按 NULL；计入警告并在预览中显示行数。
- 首行是列名时，列名去掉首尾空白；否则列名为 `column_1`、`column_2`……

### 4.3 Excel

- 用 `calamine` 读 `.xlsx`、`.xls`。calamine 读取时整个工作表在内存中，这是已知限制（界面已提示）。
- 单元格类型：数字、文本、布尔按原类型；日期时间（含 Excel 日期序号）转为日期或日期时间；错误值（`#N/A` 等）按 NULL 并计入警告；空单元格为空。
- 工作表的范围按 calamine 给出的已用区域；首行是列名时取首行文本作列名（空的用 `column_n`）。

### 4.4 预览接口返回

- 列名、前 100 行（单元格为文本、数字、布尔、日期时间或空，序列化时标明类型）、推断的类型（每列一个逻辑类型，见 4.5）、警告（列数不齐的行数等）、Excel 的工作表名列表、CSV 实际使用的编码和分隔符。

### 4.5 类型推断（只用于导入到新表）

- 每列看前 1000 行（预览时额外读取，不返回给前端），空值不参与；按以下顺序取第一个能容纳全部值的类型：
  1. 布尔：`true`/`false`（不区分大小写），或 Excel 的布尔单元格；
  2. 整数 `Int { bits: 64 }`：可选符号加数字，在 i64 范围内；
  3. 精确小数 `Decimal`：精度和小数位取各值的最大值（精度至少 10，最大 38；超过 38 时改用 VarChar）；
  4. 日期：`YYYY-MM-DD`、`YYYY/MM/DD`，或 Excel 的日期单元格；
  5. 日期时间 `Timestamp`：日期加空格或 `T` 加 `HH:MM[:SS[.fff]]`，或 Excel 的日期时间单元格；
  6. 字符串：`VarChar`，长度取最长值（按字符数）× 2，至少 50；超过 4000 时用 `Text`。
- 不推断成浮点（Excel 的数字单元格也按精确小数处理，值按 Excel 显示的最短十进制表示）。
- 全空的列推断为 `VarChar(50)`。
- 逻辑类型通过方言已有的 `native_type` 转为目标库的类型；建表语句由方言生成（`CREATE TABLE`，含可空和主键约束，标识符按方言引用）。
- 列名清理：去掉首尾空白；空的改为 `column_n`；重名的加后缀 `_2`、`_3`。

### 4.6 写入时的值转换

- 按目标列的逻辑类型把文件中的值转换为驱动的 `Value`：
  - 整数、精确小数：按文本解析，不经过浮点（Excel 数字单元格取最短十进制表示再解析）；超出范围为错误；
  - 浮点：按 f64 解析；
  - 布尔：`true`/`false`/`1`/`0`/`是`/`否`（不区分大小写），或布尔单元格；
  - 日期、时间、日期时间：4.5 中的格式，或 Excel 日期单元格；带时区的列接受末尾的 `Z` 或 `±HH:MM`；
  - 二进制：`0x` 开头的十六进制；
  - 文本、JSON、UUID 及其他：原样作为文本（UUID 校验格式）。
- 空单元格按空值选项写 NULL 或空字符串。
- 转换失败是这一行的错误，错误信息包含列名和原值（超过 100 字符截断）。

## 5. 写入（`dblens-dialect` 生成语句，`dblens-service` 执行）

### 5.1 语句生成（`dblens-dialect/src/import.rs`，无 IO）

- 输入：表的结构模型、映射到的列（顺序）、写入方式、若干行的 `Value`；输出：带占位符的语句和参数。复用 M2a 的标识符引用和占位符规则（含 PG 精确小数的 `$n::text::numeric`）。
- 每条语句最多 500 行，且参数总数不超过 30000；一批的行按此拆成若干条语句。
- 追加：
  - MySQL、MariaDB、PostgreSQL、达梦：`INSERT INTO t (c1, c2) VALUES (…), (…)`；
  - Oracle：`INSERT ALL INTO t (c1, c2) VALUES (…) INTO t (c1, c2) VALUES (…) SELECT 1 FROM DUAL`（不依赖 23ai 的多行 VALUES）。
- 清空：`DELETE FROM t`（不用 TRUNCATE：它在 MySQL、Oracle 里隐式提交，不能回滚）。
- 按主键更新（要求主键列全部已映射；非主键的映射列全部更新；只映射了主键列时退化为"不存在则插入"）：
  - MySQL、MariaDB：`INSERT … VALUES … ON DUPLICATE KEY UPDATE c = VALUES(c)`（用 `VALUES()` 兼容 MariaDB）；
  - PostgreSQL：`INSERT … VALUES … ON CONFLICT (主键列) DO UPDATE SET c = EXCLUDED.c`（只映射了主键列时 `DO NOTHING`）；
  - Oracle、达梦：`MERGE INTO t USING (SELECT :1 c1, :2 c2 FROM DUAL UNION ALL SELECT … FROM DUAL) s ON (t.k = s.k …) WHEN MATCHED THEN UPDATE SET t.c = s.c WHEN NOT MATCHED THEN INSERT (…) VALUES (s.…)`（只映射了主键列时省略 WHEN MATCHED）。
- 兼容库（如 TiDB、OceanBase MySQL 模式、openGauss）按所属家族生成。

### 5.2 执行

- 导入任务另开一个连接（`registry.connect`），不经过会话管理，与导出相同。开始前：
  - 连接的执行策略不允许 DML（只读连接）时拒绝开始；
  - 新建表时执行策略不允许 DDL 时拒绝开始。
  生成的语句不再逐条经过执行策略（开始前的确认就是确认）。
- 新建表：先执行建表语句。之后整体事务模式下失败或取消时执行 `DROP TABLE` 删除这张表；分批模式保留。
- 整体一个事务：关闭自动提交；（清空后导入时先 DELETE）；逐批执行；全部成功后提交。任何错误（包括值转换失败）或取消：回滚并结束，结果中给出第一个错误的文件行号和原因。
- 分批提交：每批一个事务（关闭自动提交，批末提交）。
  - 出错时停止：回滚这一批并结束，结果中给出出错的行号、原因和已提交的最后一行的行号。
  - 出错时跳过：回滚这一批，再把这一批逐行执行（每行一条语句，单独提交）；仍失败的行写入出错报告，继续下一批。值转换失败的行在生成语句前就写入出错报告，不发给数据库。
  - 按主键更新时，同一批中主键重复会使 PG 和 Oracle/达梦整批报错；跳过模式下逐行重试时依次执行，相当于后面的行覆盖前面的行。
- 结束时（任何情况）恢复自动提交并关闭连接，删除上传的文件。
- 执行历史：整个任务写一条，SQL 栏为 `-- 导入 <文件名> → <表名>（<写入方式>）`，行数为写入的行数，失败时记为失败并带错误信息。

### 5.3 出错报告

- 跳过模式下边导入边写，UTF-8 带 BOM 的 CSV：列为"行号"、"错误"，然后是文件的原始各列（用文件的列名）。行号为文件中的行号（CSV 按记录计，首行列名为第 1 行；Excel 为工作表的行号）。
- 放在导出的临时目录，下载方式与导出文件相同；浏览器模式下载后删除，桌面版提供"另存为"。
- 跳过的行数不设上限。

### 5.4 取消与进度

- 取消与导出相同：先置取消标志，再取连接的取消句柄；任务存好句柄后先检查标志；每批之前检查一次标志。
- 进度：状态（准备 / 建表 / 清空 / 写入 / 完成 / 失败 / 已取消）、已读行数、已写行数、跳过行数、已读字节和文件大小（CSV）、警告数。前端轮询，与导出相同。

## 6. SQL 文件任务

### 6.1 分块拆分（`dblens-dialect/src/split.rs`）

- 新增 `StreamSplitter`：`feed(&str) -> Vec<SqlStatement>` 返回本次已完整的语句，`finish() -> Option<SqlStatement>` 返回文件末尾剩下的一条。语句的 `start`/`end` 为在整个文件（转码后文本）中的字节位置；另给出语句起始的行号。
- 跨块保留的状态：当前结束符（MySQL `DELIMITER`）、是否在 PL/SQL 块中、是否在字符串 / 注释 / `$$` 引号中，以及尚未完整的那条语句的文本。
- 扫描为线性：从上次停下的位置继续，不在每块重新扫描未完成的语句。可能被块边界切开的结束符（如 `$$` 只读到 `$`、多字符的 DELIMITER）、行首命令（单独一行的 `/`、`DELIMITER xx`）要等读到足够的字符或换行再判断，文件结束时按结束处理。
- 现有的 `split_statements` 改为用 `StreamSplitter` 一次喂入全文，两边共用一套规则。
- 正确性要求：任意切块方式喂入的结果与整段拆分完全一致（语句文本、字节位置、行号）。

### 6.2 扫描与确认

- 开始后先只拆分不执行，读完全文，得到语句总数，以及执行策略的结果：
  - 有被拒绝的语句：任务结束，列出这些语句（行号和开头），不执行任何语句；
  - 有需要确认的语句，或连接是生产环境：任务进入"等待确认"，返回语句总数和需要确认的语句（最多 20 条，带行号，另给出总条数）；前端弹确认框，确认后任务继续，取消则结束。
- 用户确认一次就代表整个文件，执行时这些语句不再逐条确认。

### 6.3 执行

- 另开连接；开始前用方言的切换 schema 语句切到所选 schema。
- 第二遍读取文件，拆分后逐条执行。查询语句照常执行，结果读完丢弃（只计行数，不读大字段完整内容）。
- 出错时停止：记录错误后结束；出错时继续：记录错误后执行下一条。
- 整体一个事务：关闭自动提交，全部成功后提交；出错或取消时回滚。此模式固定为出错时停止。
- 文件中的 `BEGIN`、`COMMIT` 等事务语句照常执行，不做特殊处理。
- 取消：同 5.4；整体事务模式下回滚，否则已执行的保留。
- 结束时恢复自动提交、关闭连接、删除上传的文件。
- 执行历史：整个任务写一条，SQL 栏为 `-- 执行 SQL 文件 <文件名>`，带成功数、失败数。

### 6.4 日志与进度

- 执行日志（UTF-8 文本）：开头写连接、schema、文件名和开始时间；每条失败的语句写行号、错误和语句文本（超过 2000 字符截断）；最后写汇总（成功数、失败数、影响行数、用时）。存放与下载同 5.3。
- 任务结果中带前 100 条失败（序号、行号、错误、语句开头 200 字符）。这 100 条的完整文本留在任务中（内存）；前端点"在新查询标签中打开"时，按任务 id 和序号向后端取完整文本。第 100 条以后的失败只在日志里。
- 进度：状态（扫描 / 等待确认 / 执行 / 完成 / 失败 / 已取消）、已读字节和文件大小、已执行语句数和总数、失败数。

## 7. 对象树导出数据

- 表和视图的右键菜单"导出数据…"打开 M1c3 的导出对话框，数据来源为整张表：后端用数据标签的 `data_sql` 生成 SELECT，不带过滤；有主键时按主键排序。
- 格式、选项、默认文件名（对象名加时间）、INSERT 的默认目标表（对象的完整名称）与数据标签导出相同。

## 8. 接口（`dblens-api`）

- `POST /uploads`：上传文件（流式写入 `imports/`），返回 `{ id, name, size }`；浏览器模式和桌面模式都可用。
- `POST /profiles/{id}/imports/preview`：文件来源、格式选项、目标表（可选）→ 4.4 的预览，另带推断的类型；给出目标表时附带每列的校验结果。
- `POST /profiles/{id}/imports/ddl`：新建表的定义 → 建表语句预览。
- `POST /profiles/{id}/imports`：开始导入任务 → 任务 id。
- `POST /profiles/{id}/sql-files`：开始 SQL 文件任务 → 任务 id。
- `GET /tasks/{id}`、`POST /tasks/{id}/confirm`、`POST /tasks/{id}/cancel`、`GET /tasks/{id}/report`（出错报告或执行日志的下载）、`GET /tasks/{id}/statements/{n}`（失败语句的完整文本）。
  - 导入、SQL 文件任务和现有的导出任务共用一个任务管理（`TaskManager`，由 M1c3 的 `ExportManager` 推广而来：状态、取消、文件下载、过期清理）。现有的 `/exports` 接口保留不变，内部改用 `TaskManager`。
- 导出数据（第 7 节）沿用 `/exports`，请求中增加"整张表"这种来源。
- 桌面版：新增 `open_dialog`（系统的打开对话框，按扩展名过滤），与 M1c3 的 `save_dialog` 放在一起。

## 9. 依赖

计划的第一个任务是依赖复查（`node scripts/check-deps.mjs`，本机需先设 `NODE_USE_ENV_PROXY=1`）。新增：
- `calamine`（MIT）：读 xlsx / xls；
- `encoding_rs`（MIT / Apache-2.0）：转码。
写计划时核对：用最新的稳定版，且发布满 7 天。

## 10. 测试

- **dialect 单元测试**：
  - `StreamSplitter`：属性测试（同一段 SQL 在随机位置切成若干块，结果与整段拆分一致）；现有拆分的全部用例用两种方式各跑一遍；`$$`、`DELIMITER`、`/`、字符串、注释恰好切在块边界上的用例；
  - 导入语句的快照测试（`insta`）：5 种方言的追加、清空、按主键更新（含只映射主键列）；每条语句 500 行和 30000 参数的拆分；
  - 建表语句：各方言的类型、可空、主键、标识符引用。
- **服务层单元测试**：
  - CSV：BOM、UTF-8、GBK 的自动判断；四种分隔符的判断；引号和转义；列数不齐；
  - Excel：测试中用 `rust_xlsxwriter` 生成文件（不往仓库放二进制文件），覆盖数字、日期、布尔、错误值、空单元格；
  - 类型推断与值转换：各逻辑类型；精确小数不经过浮点；日期的各种格式；
  - 任务（假驱动）：整体事务出错回滚；分批停止；分批跳过逐行重试和出错报告；取消；SQL 文件的扫描、确认、拒绝。
- **实库测试**（5 个库，`DBLENS_TEST_*_URL`）：
  - 导入到已有表：追加 2500 行（含中文、NULL、精确小数、日期），核对行数和抽样值；清空后导入；按主键更新（一半已存在、一半新行）；整体事务中第 2000 行出错，表中数据不变；
  - 分批加跳过：混入坏行，只跳过坏行，出错报告的行号和原因正确；
  - 导入到新表：推断、建表、写入；整体事务失败时新建的表被删除；
  - 取消：导入和 SQL 文件执行到一半时取消；
  - SQL 文件：各方言的样例（MySQL 的 `DELIMITER` 加存储过程、PG 的 `$$` 函数、Oracle 和达梦的 PL/SQL 块加 `/`）；出错时停止和继续；一个约 50 MB 的生成文件，核对语句数。
- **前端单元测试**（Vitest）：列名自动匹配；向导各步的校验；写入方式的可选条件。
- **浏览器实测**（PG，中英文界面）：上传 CSV 和 xlsx、映射、导入到已有表和新表、下载出错报告、执行 SQL 文件（含确认框）、从对象树导出整表。
- **桌面版**：系统打开对话框需要用户手动验证一次。
