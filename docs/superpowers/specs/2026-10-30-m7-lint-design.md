# M7 数据库设计规范检查

日期：2026-10-30（同日修订：加条款层、人工确认，调整分期和结果统计）。上级设计：总设计 `2026-10-22-dblens-design.md`；M4a 模型与比对、M4c 文档导出。

## 1. 目标与范围

检查库或模型的结构是否符合设计规范，出具报告：**规范库 → 选规范 → 选检查对象 → 出报告**。

包括：

- 多份规范，内置 3 份，可查看、修改、复制、导入导出，内置的可恢复默认；
- 规范由条款组成，每条可开关、改严重级别、改参数；
- 检查对象：连接的一个模式，或模型文件；
- 每条条款都有结论，自动查不了的进人工确认；
- 检查结果界面，报告导出 HTML、Word、Excel，Excel 可按自查表格式输出；
- 例外：某个对象不适用某条条款时豁免并写原因；
- 自定义规则：名称正则、必备字段这类声明式规则。

不包括：

- 用户写 SQL 或脚本的规则（安全和跨库都难，后续再议）；
- 自动修复，只给修改建议；
- SQL 语句审核（这里只查结构，不查查询语句）；
- JDBC 配置、存储过程和游标的编写约束（属于开发规范，不是结构设计）。

规则来源：

- 海关集中式事务型数据库设计规范（2024 年 10 月）、海关分布式分析型数据库（GBASE）设计规范、项目组自查表，**只取与海关业务无关的部分**；
- 业界通用规约。

内置条款的文字按数洞的口径改写，不带海关字样和样例。

## 3. 规范的结构

规范分两层：**条款**是给人看的要求，决定结论和级别；**规则**是代码里的检查，挂在条款下面。

```yaml
id: strict-oltp
name: 事务型严格
builtin: true
clauses:
  - id: naming.table_length      # 条款编号，内置条款的编号不变
    section: 命名                # 分类
    text: 表名长度不超过 40 个字符
    enabled: true
    severity: error              # error / warning / info
    manual_note:                 # 自动查不全时写明要人工确认什么
    rules:                       # 挂 0 到多条规则，没有规则的是人工条款
      - id: name.max_length
        params: { target: table, max: 40 }
        databases: [all]         # 或 mysql、oracle 等
custom: []                       # 自定义规则，M7c
```

- 规则的**检查逻辑写在代码里**，规范只记开关、级别和参数。这样规则升级时规范不用改。
- 同一条规则可挂在多条条款下，参数不同。比如 `name.max_length` 分别查表、字段、索引的长度。
- 问题的严重级别取所在条款的级别，规则本身不设级别。
- 内置规范的默认值随程序发布。用户改动单独保存，只记差异，所以"恢复默认"就是删掉差异，新版本增加的条款也能自动带上。
- 用户复制出的规范完整保存，可以增删条款。M7a 能加纯文字的人工条款。
- 规范保存在本地数据库的新表 `lint_rulesets`，不放设置项（设置项有大小限制，也不便导入导出）。导入导出用 YAML。

## 4. 内置规范

| 规范 | 定位 |
|---|---|
| 数洞通用（默认） | 通用规则，大多是警告 |
| 事务型严格 | 吸收集中式规范的通用部分，大多是错误 |
| 分析型 | 吸收 GBase 规范：不建主键、外键、索引，分布设计走人工确认 |

三份规范的差异：

| 项 | 数洞通用 | 事务型严格 | 分析型 |
|---|---|---|---|
| 名称大小写 | 按数据库 | 按数据库 | 大写 |
| 名称长度 | 40 | 40 | 表 56、字段 64、其他 48 |
| 主键 | 必须有 | 必须有 | 不建 |
| 外键 | 提示 | 错误 | 错误 |
| 触发器 | 警告 | 错误 | 错误 |
| `CHAR` | 提示 | 错误 | 警告 |
| 视图、函数、存储过程 | 关闭 | 警告 | 警告 |
| 必备字段 | 创建时间、更新时间，警告 | 同左，错误 | 关闭 |

"按数据库"的含义：Oracle、达梦查大写，MySQL、PostgreSQL 查小写，SQL Server 不查。前缀比较时不分大小写，大小写只由大小写规则判断。

海关业务相关内容的处理：

- **不内置**：海关数据标准、业务网和专网的区分、`PRE`/`CUR`/`COPY_` 前缀、`INDB_TIME`。
- **改成参数**：必备字段（如 `REC_VERSION`、`BUSI_DATE`）、应用简称前缀、大小写。用户复制一份规范配上参数，就是"海关版"。

自查表把全部条款标为"强制"，内置规范按规范原文的措辞定级：不得、应对应错误，宜、审慎、尽量对应警告。

规范和自查表都写着"不得使用 CHAR、VARCHAR(NCHAR)"，疑似笔误，内置时按"不用 `CHAR`、`NCHAR`、`NVARCHAR`"处理。

## 5. 规则

现有元数据可以直接查的：

| 类别 | 规则（括号内是默认参数） |
|---|---|
| 命名 | 字符集和首字母、长度、大小写、保留字和需要加引号的名字、拼音、`PK_` `UK_` `IX_` `SEQ_` `PROC_` `FN_` `V_` 前缀、日期时间字段后缀 |
| 表 | 必须有主键、表注释、字段数（200）、字符型总字节（8092）、必备字段、遗留备份表（`_BAK` 或日期后缀）、预留字段、全部字段可空 |
| 主键 | 自增列做主键、不建主键（分析型） |
| 字段 | 字段注释、注释不等于字段名、日期不用字符型、整数不用小数类型、小数指定精度、金额不用 `FLOAT`/`DOUBLE`、`CHAR`/`NCHAR`、`LONG`、`ENUM`、大字段、`VARCHAR(4000)` 过多、不用自增列（分析型） |
| 索引 | 数量（5）、组合索引列数（5）、重复或被覆盖的索引、大字段列上的索引、函数索引、位图索引、每列都建单列索引、外键列没有索引、不建索引（分析型） |
| 约束 | 外键、触发器、视图、函数、存储过程、序列、Oracle 同义词上的 DBLINK |
| 一致性 | 同名异义、同义异名、关联字段类型不一致（启发式，只报警告） |

需要查数据的，默认关闭，开启时需确认，避免在生产库上产生负载：表数据量（2000 万行应分区）、低选择性列上的单列索引。

现有元数据取不到的，规则照常挂上，首期报**无法判断**，M7c 按需补：

- 自动更新时间戳做主键（MySQL 的 `ON UPDATE` 没有取）、自增步长、分区表的本地索引（分区信息只有文字描述）；
- 字符集（含 MySQL 的 `utf8mb4`）、存储引擎（InnoDB）；
- 表空间、跨用户授权、EVENT、临时表、Oracle 以外的 DBLINK。

**人工条款**没有挂规则，由人判断：第三范式、冗余字段、多媒体文件不入库、枚举值和编码规则写入注释、外来数据的变化写入注释、高频查询字段建索引、组合索引列序、OR 查询不建组合索引、主键值不修改、数据清理方案、ER 图、分布键选择、复制表选择。

分布键和复制表不做自动检查：现有模型没有这些信息，数洞也不为 GBase 单独适配。

拼音检测是启发式的，只报警告。函数索引按"索引列不是表中字段"判断。

## 6. 结论

每条条款有一个结论：

| 结论 | 含义 |
|---|---|
| 通过 | 规则全部通过 |
| 未通过 | 有规则发现问题 |
| 无法判断 | 规则需要的元数据取不到 |
| 待人工确认 | 人工条款，或规则通过但 `manual_note` 不为空 |
| 不涉及 | 规则的 `databases` 不含当前数据库，或人工判定不适用 |

判定顺序：未通过 → 不涉及（全部规则都不涉及）→ 无法判断 → 待人工确认 → 通过。

无法判断和待人工确认的条款，用户可以填结论（通过、未通过、不涉及）和说明，填写后按所填结论统计。

报告不打总分，只给**条款通过率**和问题数。通过率 = 通过 ÷（通过 + 未通过）。其余结论单独计数，不进分母。

## 7. 引擎

- 放在新 crate `dblens-lint`，依赖 `dblens-core` 的结构模型和 `dblens-dialect` 的标识符判断，不连库，便于测试和复用。
- 输入：`dblens_core::Schema` 和方言家族。保留字和需要引号的判断复用 `ident.rs`，要把 `is_reserved` 公开。
- 每条规则实现同一个接口，返回通过、问题列表或无法判断。问题包含对象、说明和修改建议。
- 引擎遍历启用的条款，运行其规则，汇总出条款结论。
- 服务层用 `metadata` 取结构，模型走模型文件，都转成同一种输入，所以库和模型的检查逻辑一致。
- 大库用后台任务（现有 `task`）执行，显示进度，可取消。
- 每次检查保存到本地新表 `lint_runs`：规范快照、条款结论、问题、人工结论。规范以后改了，旧结果和报告不变。

## 8. 界面

- **规范库**：左侧规范列表，右侧条款表，按分类分组，可直接改开关、级别和参数，展开可看挂的规则。
- **检查**：对象树右键或工具栏发起，选规范后开新标签显示结果。
- **结果**：顶部是通过率和各结论计数，下方是按分类分组的条款表；展开条款看问题，点问题可打开表设计器定位；待确认的条款可直接填结论和说明。
- **例外**（M7b）：在问题上右键豁免，写原因，存在规范里，按对象名匹配。

## 9. 报告

内容：封面信息（对象、规范、时间、版本、检查人）、通过率和各结论计数、条款结论总表、问题明细、人工确认清单；M7b 增加豁免清单。

- **HTML**（M7a）：单文件，便于发送和归档。
- **Word、Excel**（M7b）：复用 M4c 的 `document/docx.rs`、`document/xlsx.rs`。
- **自查表格式**（M7b）：Excel，列为序号、分类、检查项、约束、结果、说明、检查时间、检查人。约束由级别导出：错误为强制，警告为建议，提示为参考。

检查人在导出时填写。

## 10. 接口

| 接口 | 说明 |
|---|---|
| `GET/POST /api/lint/rulesets` | 列出、新建 |
| `GET/PUT/DELETE /api/lint/rulesets/{id}` | 读取、修改、删除 |
| `POST /api/lint/rulesets/{id}/reset` | 恢复默认 |
| `GET /api/lint/rules` | 全部规则的说明和默认参数 |
| `GET/POST /api/lint/runs` | 列出检查记录、发起检查（返回任务） |
| `GET/DELETE /api/lint/runs/{id}` | 读取、删除检查结果 |
| `PUT /api/lint/runs/{id}/clauses/{clause}` | 填写人工结论 |
| `GET /api/lint/runs/{id}/report` | 导出报告，`format` 选格式 |

## 11. 测试

- 每条规则用内存中的 `Table` 做单元测试，正反各一例；
- 条款结论的判定顺序逐项测试；
- 内置规范的快照，防止默认值被无意改动；
- 实库测试：在各数据库的测试库上跑一遍，确认取得到元数据，无法判断的条款和设计一致；
- 界面用真实鼠标验证完整流程，包括填人工结论和导出 HTML 报告。

## 12. 风险

- 启发式规则（拼音、同义异名）会误报：默认只报警告，并支持豁免。
- 各库元数据差异大：取不到的报"无法判断"，不算通过。
- 无法判断的条款较多时，通过率偏乐观：报告里无法判断和待人工确认的计数要和通过率并列显示。
- 内置条款的文字和编号发布后尽量不改：用户的差异和旧结果都按条款编号关联。
