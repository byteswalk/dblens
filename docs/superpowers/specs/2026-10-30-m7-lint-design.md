# M7 数据库设计规范检查

日期：2026-10-30。上级设计：总设计 `2026-10-22-dblens-design.md`；M4a 模型与比对、M4c 文档导出。

## 1. 目标与范围

检查库或模型的结构是否符合设计规范，出具报告：**规范库 → 选规范 → 选检查对象 → 出报告**。

包括：

- 多份规范，内置 3 份，可查看、修改、复制、导入导出，内置的可恢复默认；
- 每条规则可开关、改严重级别、改参数；
- 检查对象：连接的一个模式，或模型文件；
- 检查结果界面，报告导出 Word、Excel、HTML；
- 例外：某个对象不适用某条规则时豁免并写原因；
- 自定义规则：名称正则、必备字段这类声明式规则。

不包括：

- 用户写 SQL 或脚本的规则（安全和跨库都难，后续再议）；
- 自动修复，只给修改建议；
- SQL 语句审核（这里只查结构，不查查询语句）。

规则来源：

- 海关集中式事务型数据库设计规范（2024 年 10 月）、海关分布式分析型数据库（GBASE）设计规范、项目组自查表，**只取与海关业务无关的部分**；
- 业界通用规约。写规则时逐条核对原文，文档抽取的文本可能缺字。

## 3. 规范的结构

```yaml
id: strict-oltp
name: 事务型严格
builtin: true
rules:
  - id: name.max_length          # 规则编号，内置规则的编号不变
    enabled: true
    severity: error              # error / warning / info
    params: { max: 40 }
    databases: [all]             # 或 mysql、oracle 等
custom: []                       # 自定义规则，M7c
```

- 规则的**检查逻辑写在代码里**，规范只记开关、级别和参数。这样规则升级时规范不用改。
- 内置规范的默认值随程序发布。用户改动单独保存，只记差异，所以"恢复默认"就是删掉差异，新版本增加的规则也能自动带上。
- 规范保存在本地数据库的新表 `lint_rulesets`，不放设置项（设置项有大小限制，也不便导入导出）。导入导出用 YAML。

## 4. 内置规范

| 规范 | 定位 |
|---|---|
| 数洞通用（默认） | 通用规则，大多是警告 |
| 事务型严格 | 吸收集中式规范的通用部分，大多是错误 |
| 分析型 | 吸收 GBase 规范：分布键、复制表、不建外键和索引 |

海关业务相关内容的处理：

- **不内置**：海关数据标准、业务网和专网的区分、`PRE`/`CUR`/`COPY_` 前缀、`INDB_TIME`。
- **改成参数**：必备字段（如 `REC_VERSION`）、应用简称前缀、自增步长。用户复制一份规范配上参数，就是"海关版"。

## 5. 规则

| 类别 | 规则（括号内是默认参数） | 检查方式 |
|---|---|---|
| 命名 | 字符集和首字母、长度（40）、大小写、保留字、带引号的名字、拼音、`PK_` `UK_` `IX_` `SEQ_` `PROC_` `FN_` `V_` 前缀、日期时间字段后缀 | 自动 |
| 表 | 必须有主键、表注释、字段数（200）、字符型总字节（8092）、必备字段、备份表 | 自动 |
| 主键 | 不用带自动更新的时间戳、自增步长 | 自动 |
| 字段 | 字段注释、注释不等于字段名、日期不用字符型、整数不用小数类型、小数指定精度、`CHAR`、`LONG`、大字段、`VARCHAR(4000)` 过多 | 自动 |
| 索引 | 数量（5）、组合索引列数（5）、重复或被覆盖的索引、大字段列上的索引、函数索引、位图索引 | 自动 |
| 约束 | 外键、触发器、DBLINK、临时表、EVENT | 自动 |
| 一致性 | 同名异义、同义异名、关联字段类型不一致 | 半自动，只给建议 |
| 分布式 | 分布键、复制表、不建主键和索引 | 能取到元数据的自动，否则人工 |
| 设计 | 第三范式、数据清理方案、ER 图 | 人工确认清单 |

数据量、选择性这类规则要查数据，默认关闭，开启时需确认，避免在生产库上产生负载。

拼音检测是启发式的，只报警告。

规则按能否取到元数据分三种结果：**通过、未通过、无法判断**。无法判断不计入扣分，但列在报告里，比如某库取不到触发器。

## 6. 引擎

- 放在新 crate `dblens-lint`，只依赖 `dblens-core` 的结构模型，不连库，便于测试和复用。
- 输入：`Vec<Table>` 加视图、序列等对象清单，以及 `Dialect`（保留字、方言差异）。
- 每条规则实现同一个接口，输出问题列表：规则、对象、严重级别、说明、修改建议。
- 服务层用 `metadata` 取结构，模型走模型文件，都转成同一种输入，所以库和模型的检查逻辑一致。
- 大库用后台任务（现有 `task`）执行，显示进度，可取消。

## 7. 评分

`100 - 错误数 × 5 - 警告数 × 1`，下限 0，按表数归一。权重后续可调。规则数和通过率也列在报告里，分数只作参考。

## 8. 界面

- **规范库**：左侧规范列表，右侧规则表，按类别分组，可直接改开关、级别和参数。
- **检查**：对象树右键或工具栏发起，选规范后开新标签显示结果。
- **结果**：顶部是总分和统计，下方按类别或对象分组的问题表，点问题可打开表设计器定位。
- **例外**（M7b）：在问题上右键豁免，写原因，存在规范里，按对象名匹配。

## 9. 报告（M7b）

复用 M4c 文档导出的 Word、Excel 能力，增加 HTML。内容：封面信息（对象、规范、时间、版本）、总分、分类统计、问题明细、豁免清单、人工确认清单。

## 10. 接口

| 接口 | 说明 |
|---|---|
| `GET/POST /api/lint/rulesets` | 列出、新建 |
| `GET/PUT/DELETE /api/lint/rulesets/{id}` | 读取、修改、删除 |
| `POST /api/lint/rulesets/{id}/reset` | 恢复默认 |
| `POST /api/lint/runs` | 发起检查，返回任务 |
| `GET /api/lint/rules` | 全部规则的说明和默认参数 |

## 11. 测试

- 每条规则用内存中的 `Table` 做单元测试，正反各一例；
- 内置规范的快照，防止默认值被无意改动；
- 实库测试：在各数据库的测试库上跑一遍，确认取得到元数据；
- 界面用真实鼠标验证完整流程。

## 12. 风险

- 文档抽取的规则可能缺字：写规则时逐条核对。
- 启发式规则（拼音、同义异名）会误报：默认只报警告或建议，并支持豁免。
- 各库元数据差异大：取不到的报"无法判断"，不算通过。
