# DBLens 审计版（授权审批服务端）

日期：2026-10-31。状态：待用户审阅。上级设计：总设计 `2026-10-22-dblens-design.md`（7.7 节执行策略）；相关：M7 规范检查、M9 账号权限；调研：`docs/research/reports/数据库工具竞品与差异化.md`。里程碑编号 G0–G5 暂定。

## 1. 目标与范围

把 DBLens 分成两版：

- **单机版**：现有产品，桌面和本机浏览器，继续在公开仓库 `byteswalk/dblens`。
- **审计版**：面向政企的服务端，所有受控数据库操作经它执行。关键指令分级，按可配置的多级审批放行，全过程留痕并防篡改，提供统计分析，可对接客户单点登录，也有内置的用户和权限能力。

本设计取代总设计和 M9 第 11 节所说的“团队版”。M9 把团队版的前提写成“付费意愿假设得到验证”，2026-10-31 用户决定直接开始设计。

| 决定 | 结论 |
|---|---|
| 管控强度 | 执行网关：服务端托管凭据并代为执行，用户碰不到数据库密码 |
| 客户端 | 先 Web，桌面端以后加“登录服务器”模式 |
| 读数据 | 按库授权加导出审批；规则可把敏感表的查询列入审批；首期不做动态脱敏 |
| 元数据库 | PG 协议族（PostgreSQL、金仓、openGauss、瀚高）和达梦 |
| 代码归属 | 审计版在私有仓库，依赖公开仓库的 crate 和 `web/` |
| 合规目标 | 按等保三级设计，国密算法可选；不承诺商密测评，不对接密码机 |
| 实现路线 | 模块化单体 `dblens-gate`，复用现有 crate |

与 M9 的边界：M9 管**数据库自身**的账号权限；本设计管**平台用户**能对哪个库做什么。M9 的修改操作是这里的一类受控操作，要走工单。

不包括（首期）：

- 多租户 SaaS，一个客户一套部署，内部用组织划分；
- 数据库协议代理，因为达梦和 GBase 8s 的协议不公开，无法全覆盖；
- 动态脱敏、执行前备份和回滚脚本（模型留字段）；
- 分网段的执行节点（执行模块隔离在内部接口后，以后再加）；
- 硬件密码机、国密 TLS（由客户的前置网关终结）；
- 钉钉、企业微信、飞书通知和外部 OA 回写（见第 12 节后续）；
- 软件许可和激活；
- Agent、MCP 接入（以后作为“又一类操作者”接入同一守卫）。

## 2. 现状与差距

| 现状 | 问题 | 处理 |
|---|---|---|
| `Policy` 只收到 `ExecContext`（连接、环境、方言）和 `StatementInfo`（摘要） | 不知道操作者，拿不到全文和操作类型 | G0 升级接口 |
| 确认靠客户端 `confirmed` 标志 | 服务端无法验证 | 审计版忽略该标志，只认工单 |
| 数据编辑的 `apply` 只处理 `Deny`，跳过 `Confirm` | 语义不一致 | G0 收口 |
| 导出（`export/job.rs`）只校验是查询，不经过 `Policy` | 无法审批导出 | G0 接入 |
| 迁移、比对同步是预检一次，执行路径分散 | 判定和执行之间可能不一致 | G0 收口到统一入口 |
| `classify` 对 Oracle、达梦、GBase 只看首关键字 | 判不出 WHERE 和对象 | 第 4 节，先按高风险处理，再补解析 |
| 一个进程令牌、一个本地 SQLite，会话、任务、上传都不分用户 | 无多用户隔离 | 扩展点加归属校验 |
| `secrets.get` 和 `registry.connect` 散落在十余处 | 凭据来源写死 | G0 改为 `CredentialSource` |

## 3. 架构

```
浏览器（web/ + web-gate/，按能力开关显示）
   │ HTTPS + WebSocket
dblens-gate（私有仓库，可多实例）
 ├ identity    内置账号、OIDC、SAML、LDAP、CAS、会话
 ├ authz       RBAC、三员互斥、资源授权（可带时效）
 ├ guard       分类、判风险：放行 / 走工单 / 拒绝
 ├ ticket      工单、审批流、执行窗口
 ├ executor    唯一持有数据库连接的模块，解密凭据
 ├ audit       记录、哈希链、检查点、外送、统计
 ├ notify      邮件、Webhook
 └ 复用：dblens-service / -dialect / -driver / -driver-* / -lint
   │
元数据库（PG 协议族或达梦）   目标数据库（凭据只在服务端）
```

### 3.1 公开仓库的改动

只放开扩展点，单机版行为不变。

- `Policy` 升级：上下文增加操作者（`Actor`，单机版为本机用户）、完整语句、操作类型（查询、数据编辑、DDL、导入、导出、迁移、权限修改）。
- `Decision` 增加 `RequireTicket`，单机版不产生。
- `CredentialSource`：单机版包装现有 `Secrets`；审计版解密托管凭据。
- `ProfileSource`：连接配置的来源。
- 执行收口：全部路径走同一入口，增加架构测试（如禁止入口外直接调用 `registry.connect` 后执行）。
- 所有者：会话、任务、导出、上传记录归属，取用时校验。
- `dblens-api` 路由可组合，鉴权中间件可替换。
- `web/` 作为包可引用，导出入口和能力开关。

### 3.2 两版差别

| | 单机版 | 审计版 |
|---|---|---|
| 客户端 | 桌面、本机浏览器 | 浏览器，桌面端后接 |
| 用户 | 无 | 平台账号或单点登录 |
| 凭据 | 用户本机 | 服务端托管，用户看不到 |
| 确认 | 客户端确认 | 工单审批，服务端判定 |
| 留痕 | 本地历史 | 防篡改审计 |

审计版首期开放：对象浏览、SQL 编辑、数据编辑、表设计器、导入导出、账号权限、规范检查。比对同步和迁移在接入工单后开放。模型文件和 ER 图依赖本地文件，首期不开放。

### 3.3 管理界面选型

沿用现有 React 19、antd 6、TanStack Query、zustand、i18next，不另起技术栈。

| 方面 | 决定 | 理由 |
|---|---|---|
| 工程结构 | 私有仓库用 pnpm workspace，引用公开 `web/`，新增 `web-gate/` | 工作台不分叉 |
| 路由 | 新增 `react-router` | 通知里的工单链接需要可分享地址 |
| 列表和表单 | antd Table、Form，服务端分页；不用 ProComponents | 减少依赖，避免卡住 antd 升级 |
| 统计图表 | ECharts，按需引入 | Apache 许可，全离线可用 |
| 审批流配置 | 表单配置，`@xyflow/react` 只读预览 | 线性分级够用，避免配出无法校验的流程 |

工作台保持现有布局。管理台在 `/admin`，左侧导航加内容区，黑白基调不变。审批页适配手机宽度。新依赖版本到计划阶段按“最新稳定版且发布满 7 天”核定。

## 4. 关键指令识别和分级

### 4.1 风险等级

等级全局固定四级，具体内容由客户配置。

| 等级 | 默认含义 | 处理 |
|---|---|---|
| L0 | 普通查询 | 有权限即可执行 |
| L1 | 带条件的数据修改 | 有权限即可执行，重点留痕 |
| L2 | 表结构变更、导出（含超行数上限的查询转导出）、大批量修改 | 走工单 |
| L3 | DROP、TRUNCATE、无 WHERE 修改、账号权限、匿名块、无法判定的语句 | 走工单，默认多级 |

### 4.2 规则

一条规则由匹配条件和结果组成：

- 条件：操作类型、语句类型、关键字、是否带 WHERE、涉及对象（通配符）、方言、预估影响行数；
- 结果：定级、绑定审批流，或直接拒绝。

- 每种数据库内置一套规则，覆盖现有 `DefaultPolicy` 的危险语句，客户可调整。
- 安全管理员维护规则，可配置双人复核。规则按版本保存，工单和审计记录判定时用的版本。
- 规则挂在连接组上。连接组带环境标记（开发、测试、生产，可自定义），可细到连接或模式。
- 多条命中取最高等级。

### 4.3 判定原则

判不清时按高风险处理。

- 脚本先用方言拆分，逐条判定，整段取最高等级。
- 解析失败、取不到对象或 WHERE：按“未知”，默认 L3，客户可调。
- 存储过程调用、动态 SQL、匿名块内容不可见，一律 L3；具体过程名可配白名单。
- `WHERE 1=1` 这类恒真条件算无 WHERE。
- L2 以上提交时跑一次 `EXPLAIN`，影响行数只作展示和规则输入，取不到时为“未知”。
- 只在服务端判定。前端可调用同一接口提示，结果不作依据。

Oracle、达梦、GBase 现在判不出 WHERE，首期修改语句会偏严。服务端解析方案在 G2 计划阶段选型并实测。

### 4.4 数据库账号分层

规则拦不住被授权用户经已有过程或触发器间接改数据。每个受控连接可配多个托管账号：只读（L0）、读写（L1）、管理（工单执行）。部署文档建议客户配置，低权限账号是审批之外的第二层强制力。

## 5. 工单、审批和放行

### 5.1 工单

内容：目标连接和模式、完整 SQL 脚本、风险判定、规则版本、理由、期望执行窗口、关联单号（可选）。导入、迁移、表设计器和权限修改生成同样的工单，附预览 SQL；导入和迁移存文件摘要和任务配置，不存全部数据。

状态：

```
草稿 → 待审批 → 已批准 → 执行中 → 已成功 / 部分失败 / 已失败 / 结果不明
          ↓         ↓
   已驳回 / 已撤回   已过期
```

### 5.2 审批流

- 一条流由若干级按顺序组成。
- 每级配置审批人来源（角色、指定用户、申请人上级、连接组负责人）和通过方式（任一人、全部、N 人）。
- 支持转交、加签、超时提醒和转交。超时不会自动通过。
- 审批流按版本保存，工单绑定提交时的版本。

服务端强制的职责约束：申请人不能审批自己的工单；同一人不能审批同一工单的两级。

审批页显示完整 SQL、风险原因、规范检查结果（复用 M7）、影响行数预估和涉及对象。

### 5.3 防改内容和防绕过

- 提交时计算内容摘要，覆盖 SQL 全文、目标连接、模式和执行账号，由服务端签名；每条审批记录签入摘要。
- 提交后不可修改，改动必须撤回重提，审批记录清零。
- 执行时重算摘要并比对，不一致就拒绝并告警。
- 执行的 SQL 只从工单读取，不接收客户端文本。
- 批准只对这张工单有效，只能执行一次，过窗口即过期。
- 编辑器命中 L2 以上时不执行，提示“提交工单”并带上语句。

### 5.4 执行

- 执行人默认是申请人，可配置为指定 DBA 或到点自动执行。
- 用专用连接运行，和交互会话分开。
- 按序执行，失败即停，记录每条结果。
- 能用事务的整张工单包一个事务，默认开启。DDL 隐式提交的库无法回滚，审批页提前提示。
- 用元库租约抢占，多实例下只执行一次。
- 进程崩溃时工单转“结果不明”，不自动重试，由人核对后标记。

### 5.5 应急通道

默认关闭。开启后指定角色可先执行后补审批，必须填原因，立即告警安全管理员，统计单列。

## 6. 读数据管控

- 用户要先有连接、模式的权限（第 8.3 节）。
- 结果导出按 L2，走工单；批准后在窗口内执行一次，文件只给申请人，下载留痕。
- 交互查询有行数上限，超过时截断并提示申请导出。
- 规则可把敏感表列入审批，语句涉及它们就走工单。对象提取不可靠的方言按第 4.3 节处理。
- 对象树按授权过滤；元数据连接用只读账号，缓存可共享，返回前过滤。

## 7. 留痕、防篡改和统计

### 7.1 记录

范围：登录登出、权限和规则变更、凭据操作、每条语句、工单每一步、导出、管理员操作、审计本身的查询和导出。

字段：时间、操作者（含来源 IP、客户端、身份来源）、动作、目标连接和模式、SQL 全文（已脱敏）、风险等级、规则及版本、工单、结果、影响行数、耗时、错误。

不记录查询结果数据和密码。结果只记列名和行数，密码沿用 M9 的脱敏逻辑。

执行前写“开始”记录，写失败就不执行；执行后写“结果”记录。

### 7.2 防篡改

1. 哈希链：每条记录带前一条的哈希，算法 SHA-256 或 SM3，每实例一条链。
2. 检查点：定时把各链链尾合并后签名，防截断。
3. 外送：记录和检查点实时推到 syslog 或客户 SIEM。

提供校验命令和管理页面，断链告警。能同时控制元库和签名密钥的人理论上可重写记录，因此外送是必选建议，部署文档明确写出。审计表建议用只能写入的账号，归档和清理用另一账号。

### 7.3 留存

默认在线 180 天。到期先导出归档并附签名清单才能清理，由审计管理员操作，并留痕。

### 7.4 查询和统计

检索：按时间、用户、连接、对象、等级、结果、SQL 关键字组合查询，可导出 CSV、xlsx，从记录跳到工单全过程。

| 主题 | 指标 |
|---|---|
| 工单 | 数量、通过率、驳回率、平均审批时长、超时、各级耗时 |
| 风险 | 等级分布、趋势、命中最多的规则、被拒绝的尝试 |
| 用户 | 高危操作排名、非工作时间操作、登录失败 |
| 连接 | 执行量、失败率、导出量 |
| 例外 | 应急通道、结果不明、完整性告警 |

后台定时写入按天汇总表，PG 和达梦用同一套 SQL。全文检索用 `LIKE` 并强制时间范围，不引入搜索引擎。月度报告复用现有文档导出（docx、HTML）。

## 8. 用户、权限和单点登录

### 8.1 内置账号

用户、组织树、用户组。密码用 Argon2id，策略可配（长度、复杂度、有效期、历史、失败锁定）。可选 TOTP。空闲超时、并发限制、强制下线。

### 8.2 单点登录

一套部署可启用多个身份提供方。

| 协议 | 方案 | 说明 |
|---|---|---|
| OIDC | `openidconnect` crate | 覆盖 Keycloak、Azure AD 和多数国产身份平台 |
| LDAP / AD | `ldap3` crate | 含定时同步组织和用户组 |
| CAS | 自行实现票据校验（2.0/3.0） | 协议简单 |
| SAML 2.0 | G4 实测后定 | `samael` 依赖 C 库 xmlsec，影响信创编译；不行就纯 Rust 校验，或经 Keycloak 中转 |

- 首次登录自动建号，可关闭改为预开通；外部组按映射表对应内部角色。
- 外部身份失效后下次登录失败；LDAP 同步到禁用时立即吊销会话。
- 单点登录故障时，只有本地应急管理员可用本地密码，使用即告警。
- 身份提供方是接口，客户自定义协议按项目定制。

### 8.3 权限

三员互斥由服务端强制，不设全能超级管理员：

| 角色 | 职责 | 不能做 |
|---|---|---|
| 系统管理员 | 用户、连接、部署配置 | 看审计、改规则 |
| 安全管理员 | 风险规则、审批流、授权 | 用户管理、看审计 |
| 审计管理员 | 只读审计和统计 | 任何配置 |

业务角色：申请人、审批人、DBA，可自定义。

资源授权：用户或组 → 连接组、连接、模式 → 只读、读写、DDL、导出、管理。可带有效期和时段。权限申请走同一工单流程，到期自动回收。

### 8.4 凭据托管

- 信封加密：每条密码一个数据密钥，算法 AES-256-GCM 或 SM4；
- 主密钥不进元库，从环境变量或受保护文件读取，留 KMS 接口；
- 写入后界面和接口都读不出，只能替换；
- 支持主密钥轮换。

### 8.5 会话

服务端会话，`HttpOnly`、`SameSite` Cookie，加 CSRF 防护和现有 Origin 校验。WebSocket 复用同一会话。API 令牌单独发放，用于外部集成，不能用于交互执行。

## 9. 部署

- 交付一个 `dblens-gate` 二进制、前端静态文件和可选的 JDBC 桥接。
- 全离线，默认不访问外网，更新检查默认关闭。
- 平台：Linux x64、ARM64（麒麟、统信），LoongArch 尽力。Windows 不作生产平台。
- 提供离线安装包、systemd 服务和 Docker 镜像。
- 管理 Oracle、达梦、GBase 时需相应客户端或 JRE，由安装检查工具提示。

### 9.1 元数据库

- 经现有 `Driver`/`Connection` 接口访问：PG 协议走原生驱动，达梦走 JDBC 桥接。
- 选达梦作元库时必须带 JRE。桥接崩溃时自动拉起，期间工单和受控执行暂停。
- 只用两者共有的 SQL 子集：行锁、事务、标准类型；不用 `LISTEN/NOTIFY`、JSONB。后台任务短轮询。
- 迁移带版本号，方言差异集中管理，全部迁移在两种库上测试。

### 9.2 高可用

- 多实例在负载均衡后，平台会话存元库。
- 编辑器会话和 WebSocket 绑定实例，需要粘性路由。实例宕机时会话断开，未提交事务由数据库回滚，用户重连。
- 工单执行和定时任务用元库租约抢占。
- 元库高可用用客户现有体系。

### 9.3 备份和升级

备份元库，并单独保管主密钥，两者缺一无法恢复托管密码。提供备份校验命令，恢复后自动校验审计链。滚动升级要求迁移向后兼容一个版本，否则明确提示停机升级。

### 9.4 通知

首期邮件和通用 Webhook。Webhook 不带 SQL 全文和密码，只带工单号和链接。

## 10. 错误处理

| 情况 | 行为 |
|---|---|
| 审计写入失败 | 不执行，返回错误，告警 |
| 元库不可用 | 受控执行全部暂停，已运行的语句结束后写结果，写不进则本地落盘待补 |
| 摘要不一致 | 拒绝执行，告警安全管理员 |
| 超出执行窗口 | 工单过期，需重新提交 |
| 执行中实例宕机 | 工单转“结果不明”，人工核对 |
| 目标库断开 | 工单失败并记录已完成语句 |
| 身份提供方不可用 | 显示错误；应急管理员可登录 |
| 主密钥缺失或不匹配 | 启动失败，不进入降级运行 |
| 外送不可用 | 本地排队重试并告警，不阻塞执行 |

## 11. 测试和验收

- G0：架构测试保证无绕过路径，单机版全量回归。
- 集成：防绕过、防改内容、职责约束、三员互斥。
- 故障：并发抢占、实例宕机、桥接崩溃、元库中断。
- 身份：Keycloak、OpenLDAP、Apereo CAS 容器。
- 元库：PG、金仓、openGauss、达梦全量迁移和业务测试。
- 界面：真实鼠标和截图，含暗色主题和中英文。

总验收：

- 发起、审批、执行、留痕、统计的完整链路走通；
- 任何入口都绕不过 L2 以上审批；
- 改一字节工单内容就执行失败；
- 篡改或截断审计记录，校验能发现；
- 申请人自批、三员兼任被服务端拒绝；
- 哨兵密码不出现在任何落盘内容里。

## 12. 分期

每期单独写计划。G0 在公开仓库，其余在私有仓库。

| 期 | 内容 | 依赖 |
|---|---|---|
| G0 公开仓库改造 | `Policy` 升级、执行收口（含导出）、扩展点、所有者校验、前端导出和能力开关 | 无 |
| G1 底座 | `dblens-gate`、元库（PG 系先行）、内置账号、RBAC 与三员、连接托管、资源授权、Web 工作台接入、基本审计记录 | G0 |
| G2 审批闭环 | 风险规则、审批流、工单、执行器、管理台、邮件和 Webhook | G1 |
| G3 审计 | 哈希链、检查点、外送、查询、统计、报告 | G1 |
| G4 单点登录 | OIDC、LDAP/AD、CAS、SAML | G1 |
| G5 政企交付 | 达梦元库、国密、高可用实测、信创平台、离线包 | G2–G4 |
| 后续 | 桌面端接入、IM 通知、动态脱敏、执行前备份、执行节点、Agent 接入、OA 回写 | |

## 13. 风险

| 风险 | 应对 |
|---|---|
| Oracle、达梦的服务端解析能力不足 | 默认偏严；G2 计划阶段选型实测 |
| 执行收口影响单机版 | 架构测试加全量回归，G0 独立交付 |
| 达梦元库依赖 Java 桥接 | PG 系先行；故障时暂停受控执行，不放行 |
| 私有和公开仓库版本漂移 | 私有仓库锁定公开仓库的提交，升级时跑全量测试 |
| SAML 的 Rust 库不适合信创 | G4 实测，备选纯 Rust 校验或中转 |
| 信创平台 WebView 问题 | 审计版只用浏览器，不受影响 |
