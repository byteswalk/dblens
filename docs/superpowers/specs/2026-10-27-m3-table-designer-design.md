# M3 表设计器 设计

日期：2026-10-27。上级设计：总设计文档 `docs/superpowers/specs/2026-10-22-dblens-design.md` 第 11 节（M3 结构设计："表设计器：列、索引、约束、注释、分区（只读）。编辑后生成变更列表，再生成 DDL，预览后执行"）与第 6.2 节（方言接口：变更列表 → DDL）。

## 1. 目标与范围

- 新建表和修改已有表：列、主键、唯一约束、索引、外键、检查约束、表注释和列注释；分区信息只读展示；
- 编辑后由后端比对出变更列表，按方言生成 DDL，预览后执行；
- 库不支持的修改（如调整列顺序）生成重建表的脚本。

不做：
- 视图、序列、存储过程、触发器的编辑；
- 已有表改名；
- 把表结构复制到其他库（属于 M5 迁移）；
- 分区的编辑；
- MySQL 的表选项（引擎、字符集）和 PG、Oracle 的存储参数的编辑。

## 2. 已定的决策（2026-10-27 与用户确认）

| 问题 | 结论 |
|---|---|
| 范围 | 一份做完：新建和修改，含列、主键、唯一、索引、外键、检查约束、注释；分区只读 |
| 库不支持的修改 | 生成重建表的脚本（建新表、复制数据、核对行数、替换旧表、重建依赖） |
| 何时重建 | 方言确定不支持时自动重建；预览中也可手动切换为重建（如 Oracle 有数据时改类型） |
| 界面 | 独立标签页，子标签：列、索引、外键、约束、选项、SQL 预览 |
| 类型编辑 | 按方言的类型下拉（可自由输入），长度和小数位单独填 |
| 实现方案 | 方案 A：前端编辑草稿表（每项带 `origin`），后端比对出变更列表再生成 DDL；比对逻辑留给 M4 复用 |

## 3. 变更模型与比对（`dblens-dialect/src/design/`，无 IO）

### 3.1 输入

`diff_table(original: Option<&Table>, draft: &Table, renames: &Renames) -> Result<Diff>`：
- `original` 为空表示新建表；
- `Renames { columns, indexes, constraints }`：各为"新名 → 原名"。前端在内部用 `origin` 跟踪每一项原来的名字，发送时整理成 `Renames`；核心结构模型 `Table` 不加字段。M4 比对两份模型时用改名检测算出 `Renames`，复用此函数。

### 3.2 校验（先于比对）

- 名字不为空；同一张表内的列、索引、约束各自不重名；类型不为空；
- 主键、唯一、索引、外键引用的列必须存在；外键两边的列数一致；
- 被删除的列仍被未删除的约束或索引引用时报错；
- 主键列自动视为 NOT NULL（给出提示，不算错误）；
- 错误带位置（子标签 + 行号 + 字段）。有错误时不生成 DDL。

### 3.3 变更列表 `TableChange`

- 表：`CreateTable(Table)`（新建表，整张表一次生成）、`SetTableComment`；
- 列：`AddColumn { column, after }`、`DropColumn`、`RenameColumn { from, to }`、`AlterColumn { from: Column, to: Column }`（带改前和改后的完整定义，由方言决定写法）、`MoveColumn { name, after }`；
- 约束与索引：主键、唯一、检查、外键、索引各自的 `Drop` / `Add`；`RenameIndex`（只改了名字时；其他改动一律先删后建）。

### 3.4 比对规则

- 列按 `Renames` 配对。类型比较不区分大小写、忽略多余空格；默认值、注释按原文比较。草稿从原表复制而来，未动过的项自然相等；
- 约束和索引按名字（经 `Renames` 换算）配对，内容不同则先删后建；
- 改了名的列：引用它的约束和索引按新名重写，不算改动。

### 3.5 输出 `Diff`

- `changes`：按执行顺序排好：删外键 → 删其他约束和索引 → 列（删除、改名、修改、新增、调整顺序）→ 建主键、唯一、检查、索引 → 建外键 → 注释；
- `unsupported`：方言确定不支持的改动及原因（如"PG 不能调整已有列的顺序"），不为空时改用重建（第 5 节）。

### 3.6 类型目录

方言提供 `type_catalog()`：该库的常用原生类型，每个类型标明参数形式（无参数 / 长度 / 精度加小数位；Oracle 字符类型另有 BYTE / CHAR 长度单位）。前端据此拼出原生类型文本；后端解析出逻辑类型用于校验。兼容库沿用所属家族的列表，变体补充少量特有类型。

## 4. 各方言的 DDL 生成

### 4.1 共同规则

- 入口 `Dialect::design_sql(schema, &Diff) -> Vec<DesignStatement>`，每条语句带 `sql` 和对应的变更序号；
- 新建表复用现有的 `table_ddl`（"查看 DDL"用的同一份），补上注释和索引的语句；
- 标识符用现有的 `ident` 引用；注释写成字面量；默认值和检查约束的表达式按原文写入（界面提示字符串要加引号）；
- `design_caps()` 告诉前端哪些可用：能否调整列顺序、外键的 ON DELETE / ON UPDATE 选项、索引方法、是否支持检查约束和降序索引列、自增的写法。不支持的选项在前端禁用。

### 4.2 MySQL 家族（MySQL、MariaDB、OceanBase、TiDB、PolarDB）

- 修改已有表时所有改动合成一条 `ALTER TABLE`（多个子句）；TiDB 6.2 以前逐条执行（变体覆盖）；
- 修改列和调整顺序：`MODIFY col 完整定义 [FIRST | AFTER x]`；
- 改名：MySQL 8.0+、MariaDB 10.5+ 用 `RENAME COLUMN`，更早的版本用 `CHANGE old new 完整定义`（按 `version.rs`）；
- 列注释和自增写在列定义里；表注释 `COMMENT = '…'`；
- 删外键 `DROP FOREIGN KEY`；删检查约束：MySQL `DROP CHECK`，MariaDB `DROP CONSTRAINT`；索引改名 `RENAME INDEX`（不支持的旧版本先删后建）。

### 4.3 PG 家族（PostgreSQL、金仓、openGauss、瀚高）

- 每项改动一条语句；
- 改类型 `ALTER COLUMN c TYPE t USING c::t`（总带 USING）；`SET` / `DROP NOT NULL`、`SET` / `DROP DEFAULT`；`RENAME COLUMN`；
- `COMMENT ON COLUMN` / `COMMENT ON TABLE`；
- `RENAME CONSTRAINT`；`ALTER INDEX … RENAME TO`；索引用独立的 `CREATE INDEX`，可选索引方法；
- 自增：新列 `GENERATED BY DEFAULT AS IDENTITY`；已有列 `ADD` / `DROP IDENTITY`；默认值为 `nextval(...)` 的 serial 列改变自增属性算不支持；
- 修改生成列的表达式、调整已有列的顺序算不支持。

### 4.4 Oracle

- `ADD (col 定义)`；`MODIFY (col 类型 DEFAULT … NULL / NOT NULL)` 只写变化的部分（重复的 NOT NULL 会报 ORA-01442）；去掉默认值写 `DEFAULT NULL`；`RENAME COLUMN`；
- `ADD` / `DROP CONSTRAINT`、`RENAME CONSTRAINT`；`CREATE INDEX`、`ALTER INDEX … RENAME TO`；
- 外键只有 `ON DELETE CASCADE` / `SET NULL`，没有 ON UPDATE；
- `COMMENT ON`；
- 自增：新列 `GENERATED BY DEFAULT AS IDENTITY`；已有列改为或取消自增算不支持（ORA-30673）；
- 调整已有列的顺序算不支持；有数据时改类型可能被拒绝（ORA-01439），由用户在预览中手动切换为重建。

### 4.5 达梦

- 大体同 Oracle：`ADD COLUMN`、`MODIFY`、`RENAME COLUMN`、`COMMENT ON`；
- 自增：新列 `IDENTITY(1,1)`；已有列改变自增属性算不支持；
- 调整已有列的顺序算不支持；
- 语法以实库测试为准，拿不准的操作标为不支持，交给重建。

### 4.6 提交方式

MySQL、Oracle、达梦的 DDL 自动提交，中途失败时已执行的不回滚；PG 家族整体放在一个事务中（第 6.3 节）。预览中写明。

## 5. 重建脚本

### 5.1 触发

`Diff.unsupported` 不为空时自动重建；用户在预览中打开"用重建方式执行"时也重建。新建表从不重建。

### 5.2 生成前读取的依赖信息

新增元数据查询模板（每个方言）：
- 其他表指向本表的外键；
- 依赖本表的视图（含物化视图）；
- 本表的触发器的完整 DDL（复用 `ddl_query`）；
- 本表的授权；
- 表的存储属性：MySQL 的引擎、字符集、排序规则；PG、Oracle、达梦的表空间。

### 5.3 拒绝重建

- 分区表；
- PG 家族中有视图或物化视图依赖本表（列出这些视图）。

### 5.4 步骤

1. 建新表 `<表名>_dblens_new`（超长时截断并加短哈希），只建列和 NOT NULL，保留存储属性；保留不了的属性列为提示；
2. `INSERT INTO new (列…) SELECT … FROM old`：保留的列（含改名的）从旧列取值，类型变了的套 `CAST(old AS 新类型)`；新增的列不出现，取默认值；自增列照原值写入（达梦先 `SET IDENTITY_INSERT … ON`，复制后关闭）；
3. 核对两表的 `COUNT(*)`，不一致即停止（由程序执行）；
4. 删除其他表指向本表的外键；
5. 删除旧表，新表改回原名；
6. 建主键、唯一、检查约束、索引、触发器、表注释和列注释；
7. 重建其他表指向本表的外键；
8. 收尾：自增接续（PG 用 `setval` 或 `RESTART` 接到当前最大值之后，Oracle 用 `START WITH LIMIT VALUE`，MySQL、达梦自动接续）；PG、Oracle、达梦按原授权重新 GRANT（MySQL 的授权按表名记录，不受影响）；Oracle、达梦重新编译依赖本表的失效视图。

### 5.5 预览

- 顶部醒目标出"将重建表"和原因；
- 完整列出脚本，由程序执行的步骤以注释行显示（如 `-- 核对行数（由 DBLens 执行）`）；
- 提示：重建期间不要写入这张表（复制之后写入的数据会丢失）；大表耗时长；行数估计（来自统计信息）；未能保留的属性。

### 5.6 失败

- PG 家族：整体一个事务，任何一步失败全部回滚；
- 其他库：第 3 步（含）之前失败，删除新表，旧表不受影响；第 5 步之后失败，数据已在改回原名的新表中，列出未执行的语句（可在新查询标签中打开），日志写明执行到哪一步。

## 6. 接口与执行

### 6.1 接口（`dblens-api/src/design.rs`）

| 接口 | 说明 |
|---|---|
| `GET /profiles/{id}/design/caps` | 当前连接（按识别出的变体和版本）的 `design_caps` 和类型目录 |
| `GET /profiles/{id}/design/table?schema=&name=` | 原表的 `Table`、行数估计、`fingerprint`（原表内容的哈希）；直接从库读取，不走缓存 |
| `POST /profiles/{id}/design/preview` | 请求 `{ schema, name?, draft, renames, rebuild, fingerprint? }`（新建时无 `name`）；返回 `errors`（带位置）、`changes`（可读摘要，如"修改列 price：类型 NUMBER(10,2) → NUMBER(12,2)"）、`statements`、`rebuild`（是否重建、原因、是否被拒绝及原因）、`warnings`、`transactional` |
| `POST /profiles/{id}/design/apply` | 请求同预览，返回任务编号 |

执行时后端用草稿重新生成语句，不接受前端传来的 SQL。

### 6.2 结构冲突

执行前重新读表并与 `fingerprint` 比较，不一致时拒绝："表结构已被修改，请刷新后重新编辑"。设计器提供"重新加载"（丢弃草稿）。

### 6.3 执行

- 复用 M2b 的 `TaskManager`：进度、取消、执行日志；进度和结果显示在设计器标签内，不弹全局通知；
- 用连接池中单独的连接，不占查询标签的会话；
- PG 家族 `BEGIN … COMMIT`；其他库逐条执行；
- 每条语句过 Policy：只读连接或被拒绝的语句在预览阶段标出，不能执行；生产环境沿用 M2a 提交改动的做法，在确认框中醒目提示；
- 取消：普通修改中断当前语句（PG 回滚全部，其他库停在当前位置并列出未执行的语句）；重建只能在第 5 步之前取消，取消后删除新表；
- 执行的每条语句记入执行历史。

### 6.4 完成后

- 本 schema 的元数据缓存失效；有其他表指向本表的外键时，相关 schema 也失效；
- 前端刷新对象树；设计器重新加载这张表作为新的基准；新建表成功后标签转为编辑这张表；已打开的这张表的数据标签刷新列信息；
- 失败时显示失败的语句、数据库的报错、执行到哪一步；未执行的语句可"在新查询标签中打开"。

### 6.5 只拿 SQL

预览中的"复制 SQL""在新查询标签中打开"。重建脚本中由程序执行的步骤在复制出的 SQL 中是注释，注明需要人工核对。

## 7. 前端设计器（`web/src/features/design/`）

### 7.1 标签与入口

- 新标签类型 `design`，参数 `{ profileId, schema, table? }`（无 `table` 为新建）；
- 标题：表名；新建时"新表"，保存后换成表名；悬停显示连接、schema、表名；
- 有未保存的改动时标题前显示圆点，关闭标签或程序时提示；重启后标签恢复，草稿不保留；
- 入口：对象树表的右键"设计表"、schema 的右键"新建表"；数据标签工具栏"设计"；标题栏"文件"菜单"新建表"（以当前选中的 schema 为准）。

### 7.2 状态

- `designStore.ts`（写法同 M2a 的 `editStore`）：原表、`fingerprint`、草稿、每一项的 `origin`、是否手动重建；
- 改动标记：新增的行绿色，修改的单元格黄色，删除的行加删除线（可还原）；每行"还原此行"，底部"撤销全部"。

### 7.3 子标签

- **列**（antd Table 行内编辑）：名称、类型（可搜索、可自由输入的 AutoComplete）、长度、小数位（按类型启用）、长度单位（仅 Oracle 字符类型）、非空、主键、自增、默认值、注释。选中行时下方属性面板编辑生成列表达式、显示原生类型全文。操作：新增（插在选中行之后）、删除、上移、下移（Alt+↑/↓）。库不能调整列顺序时仍可移动已有列，SQL 预览中标出"将重建表"；
- **索引**：名称、列（多选，可调顺序和降序，可填表达式）、唯一、方法；主键和唯一约束自动生成的索引不列出；
- **外键**：名称、列、引用的 schema 和表、引用列（从元数据选）、ON DELETE、ON UPDATE（方言不支持的选项禁用）；
- **约束**：唯一约束、检查约束两组；
- **选项**：表名（仅新建时可编辑）、表注释、主键名和主键列顺序、分区信息（只读）、行数估计；
- **SQL 预览**：改动后约 300 毫秒自动预览；用现有的只读 SQL 查看器；顶部显示是否重建和原因、提示、是否在一个事务中执行。校验错误在各子标签上显示数目，出错的单元格标红，悬停显示原因。

### 7.4 保存

Ctrl+S 或"保存"打开确认框：变更摘要、完整 SQL、"用重建方式执行"开关（确定不支持时强制打开且不可关闭）、提示、生产环境横幅；按钮：执行、复制 SQL、在新查询标签中打开、取消。执行后进度显示在设计器底部，可取消。

### 7.5 其他

- 新词条文件 `design.json`（中、英），英文用 `_one` / `_other`；
- 不新增前端依赖（上下移动用按钮，不引入拖拽库）。

## 9. 测试

- **dialect 单元测试**：
  - 比对：每种变更（加列、删列、改名、改类型、改空值、改默认值、改注释、调整顺序；主键、唯一、检查、外键、索引的增删改；索引只改名）；列改名后约束和索引跟随且不算改动；无改动时变更列表为空；类型比较不区分大小写和多余空格；
  - 校验：重名、空名、引用不存在的列、外键列数不一致，错误位置正确；
  - 生成：每个方言每种变更的快照测试（`insta`）；版本差异（MySQL 8 与 MariaDB 10.4 的改名、TiDB 拆分）；不支持的操作进入 `unsupported`；
  - 重建脚本：每个方言一份完整脚本的快照（CAST、自增、指向本表的外键、触发器、授权、存储属性）；拒绝的情况（分区表、PG 依赖视图）；名字超长截断；
  - 新建表：与 `table_ddl` 一致，再比对无差异。
- **实库测试**（5 个库，`DBLENS_TEST_*_URL`；达梦串行运行）：
  - 普通修改：建带主键、唯一、检查、外键、索引、注释和数据的测试表；执行加列、改名、改类型（变宽）、改空值和默认值、改注释、增删索引、改外键；重新读取元数据与草稿比对，差异为空；
  - 重建：每个库调整一次列顺序（MySQL 走 ALTER，其他库走重建），核对数据和行数不变、约束、索引、注释、触发器、指向本表的外键都在、自增的下一个值正确、授权恢复（PG、Oracle、达梦）；Oracle 对有数据的列手动重建，VARCHAR2 转 NUMBER；
  - 失败与取消：PG 中途失败全部回滚；其他库失败时列出剩余语句；重建中途取消，新表被删除，旧表不变；
  - `fingerprint` 冲突：打开后从另一个会话改表，执行被拒绝。
- **接口测试**（假驱动）：预览和执行；校验错误、拒绝重建、只读连接、Policy 拦截。
- **前端单元测试**（Vitest）：`designStore` 的增删改、还原、撤销全部；改名时 `origin` 跟踪和整理出的 `Renames`；类型与长度、小数位的启用规则及拼出的原生类型文本；改动标记。
- **浏览器实测**（PG 和 MySQL，中英文界面）：新建表；修改列、索引、外键；PG 上调整列顺序触发重建；复制 SQL、在新查询标签中打开；生产环境的确认；未保存时关闭标签的提示。
