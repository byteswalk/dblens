# M4a 模型与比对 设计

日期：2026-10-27。上级设计：总设计文档 `docs/superpowers/specs/2026-10-22-dblens-design.md` 第 3 节、第 11 节（M4 模型："YAML 模型文件（可放进 git）、从库反向生成模型、三层比对（表 → 列 → 约束和索引，带改名检测）、同步脚本、ER 图、数据字典和设计文档导出"）。

## 1. 目标与范围

M4 拆成三份（2026-10-27 与用户确认），按顺序做：
- **M4a 模型与比对**（本文）：YAML 模型文件；从库反向生成模型；在模型里编辑表；三层比对与改名识别；同步到数据库或写回模型。
- M4b ER 图：在模型上画 ER 图，按列画外键连线，自定义逻辑外键，布局存回模型目录。
- M4c 文档导出：数据字典和设计文档，docx / html / markdown，可选模板。

M4a 不做：
- ER 图、逻辑外键（M4b）；文档导出（M4c）；
- 视图、序列、存储过程、触发器进模型；
- 跨数据库家族的比对和同步（M5 迁移）；
- 监视模型文件的变化（靠"重新加载"和保存时的冲突检测）。

## 2. 已定的决策（2026-10-27 与用户确认）

| 问题 | 结论 |
|---|---|
| 拆分 | 三份：M4a 模型与比对、M4b ER 图、M4c 文档导出；先做 M4a |
| 模型与数据库类型 | 一个模型绑定一种数据库（变体、兼容模式、版本），存原生类型；跨家族的比对和同步留给 M5 |
| 文件组织 | 一个模型一个目录：`model.yaml` 加 `tables/<schema>/<表>.yaml`，一张表一个文件 |
| 模型里编辑 | 可以，复用 M3 的表设计器；模型面板中新建、删除、改名表；改名记下来供比对 |
| 比对与同步 | 任意两边（模型或数据库 schema）比对；结果三层展示、可勾选；目标是数据库时生成脚本并可执行，目标是模型时写回文件 |
| 模型内容 | 只有表（与 M3 设计器相同的内容，分区只读） |
| schema | 一个模型可以有多个 schema；比对一次一对，两边名字可以不同 |
| 方案 | 后端读写模型目录（`dblens-service`），比对和同步脚本在方言层（`dblens-dialect`，不做 IO） |

## 3. 模型文件

### 3.1 目录结构

```text
<模型目录>/
  model.yaml
  tables/<schema>/<表名>.yaml
```

- 文件名是 schema 名和表名；含文件系统不允许的字符（`/ \ : * ? " < > |`、控制字符、结尾的点或空格）或 Windows 保留名（`CON`、`PRN`、`AUX`、`NUL`、`COM1`–`COM9`、`LPT1`–`LPT9`）时用 `%XX` 转义（`%` 本身也转义）。
- 表文件里另记表名原文，读取时以文件内容为准。
- YAML 读写用 `serde-saphyr`（纯 Rust，维护中，支持读写；`serde_yaml` 已停止维护）；版本在实施计划的依赖复查中确认。

### 3.2 `model.yaml`

```yaml
format: 1
name: 订单系统
description: 可选
database:
  variant: kingbase          # 与 Variant 的序列化名称相同
  compat: oracle             # 只有人大金仓、openGauss 写
  version: 120100            # 编码后的版本；不写时按最新版本
schemas: [shop, crm]
renames:                     # 编辑时记下的改名（新名 → 原名）
  shop:
    tables: { orders_new: orders }
    columns: { orders_new: { amount: total } }
```

### 3.3 表文件

`dblens_core::schema::Table` 的 YAML 形式：

- 写：字段顺序固定；空列表、None 不写；逻辑类型和列序号不写（逻辑类型读取时按方言由原生类型推出，序号按先后顺序）；多行文本用块写法。
- 读：未知字段保留，保存时原样写回（M4b 的扩展字段、手写的字段不丢）。
- 写文件先写临时文件再改名。

### 3.4 出错与版本

- 某个表文件解析失败：模型照样打开，这张表标为"文件有错"（路径、行号、原因），不能编辑和比对，其余表不受影响。
- `format` 比程序认识的新：只读打开，提示升级。

## 4. 打开、反向生成与编辑

### 4.1 服务层

- `ModelStore`（`dblens-service/src/model/`）：打开的模型（编号 → 路径、模型信息）；表文件按需读取并缓存，按修改时间和长度判断是否要重读。
- 最近打开的模型记在设置 `ui.models.recent`。
- 浏览器模式填服务器上的路径；只有监听本机地址的浏览器模式和桌面程序允许打开模型（与 M2b 选本机文件的规则相同），否则返回禁止。

### 4.2 新建与反向生成

- 新建空模型：目录、名称、数据库类型（产品、版本；人大金仓、openGauss 另选兼容模式）。目录必须不存在或为空。
- 反向生成：选连接和一个或多个 schema；作为任务（`TaskKind::Reverse`）执行，有进度、可取消；读表跳过元数据缓存（与 M3 `design_table` 相同）；模型的数据库类型取该连接识别出的变体、兼容模式和版本；目标目录要求同上。

### 4.3 编辑

- 模型面板：模型 → schema → 表；表的新建、删除、改名、用设计器打开；"重新加载"；"在文件管理器中显示"（只有桌面程序）。
- 设计器标签的目标多一种 `{ model, schema, table | null }`：类型目录和能力取模型的数据库类型（`Dialect` 由 `model.yaml` 构造）；校验与 M3 相同；保存只写这张表的文件；"SQL 预览"子标签换成"与库比对"的入口。
- 改名：
  - 表改名：改文件名，更新其他表外键对它的引用；
  - 列改名：更新本表的约束、索引和其他表外键对它的引用；
  - 记入 `renames`；新名本身是上次改名的结果时沿用最初的原名；改回原名时删去这条记录。
- 冲突：打开表时记下文件内容的指纹，保存时文件已变（如在 git 中切换了分支）就拒绝，提示重新加载。

### 4.4 接口

`/models`：打开、新建、关闭、列表；`/models/{id}`：模型信息的读写；`/models/{id}/tables`：表列表；`/models/{id}/tables/{schema}/{name}`：读、保存、删除；新建表；改名；`/models/reverse`：反向生成（返回任务 id）。

## 5. 比对（`dblens-dialect`，不做 IO）

### 5.1 输入与方向

两边各是一组表（模型的一个 schema 或数据库的一个 schema），分"源"和"目标"；结果描述"怎样修改目标才与源一致"。界面可交换两边。

### 5.2 表的配对

1. 按名字配对：MySQL 家族按库的 `lower_case_table_names` 决定是否区分大小写（模型按其数据库类型的默认值），其他家族区分。
2. 模型的 `renames` 直接作为配对。
3. 剩下的表推测改名：列名的 Jaccard 系数 ≥ 0.7 且列数差不超过 2 的，作为"疑似改名"；默认不采用（显示为删除加新增），用户选"按改名处理"后按改名重新比对。
4. 配上对的表用 M3 的 `diff_table`；列的改名：记下的直接采用；推测的（删一列、加一列，类型相同、位置相差不超过 1）要用户确认。

### 5.3 选项

- 忽略注释（默认否）；
- 忽略列顺序（默认否）；
- 忽略系统生成的约束名、索引名（默认是：如 Oracle 的 `SYS_C…`、PG 的 `<表>_pkey`、MySQL 的 `PRIMARY`，按内容配对）；
- 类型、默认值的写法差异视为相同：沿用并补充 M3 的 `same_type`；默认值去掉库加的类型转换（如 `'abc'::character varying`）后比较。

### 5.4 输出

- `SchemaDiff`：每张表一项，状态为新增、删除、改名、修改、相同，疑似改名另标；修改的表带 M3 的变更列表，按类别（列、主键、唯一、外键、检查、索引、注释）分组。
- 每项变更有编号，勾选、同步都按编号。
- 依赖校验：勾选的组合有冲突时给出提示（如没勾选"新建表 B"，却勾选了"加指向 B 的外键"）。

## 6. 同步

### 6.1 目标是数据库

- 脚本顺序：删外键（要删除、要修改的，以及指向将被删除的表的）→ 删表 → 表改名 → 逐表修改（M3 `design_sql`；不支持的走 M3 重建，依赖信息在预览时读取）→ 建表（不带外键）→ 加外键。
- 执行：预览后作为任务执行，复用 M3 的执行器（执行策略、生产环境确认、PG 家族一个事务、其他库失败时列出未执行的语句、执行历史）。执行前重读目标 schema 中涉及的表并重新比对，与预览时不同则拒绝。
- 不执行时：复制脚本、在新查询标签中打开、另存为 `.sql`（桌面程序用系统对话框，浏览器模式下载）。
- 安全默认值：删除表、删除列默认不勾选，勾选后在预览中标红；不采用改名时提示会丢数据。
- 结束后刷新目标 schema 的元数据缓存；比对标签自动重新比对。

### 6.2 目标是模型

- 方言层 `apply_changes(&Table, &[TableChange]) -> Result<Table>`：把勾选的变更应用到目标表；新增、删除表对应建、删文件。
- 写回前核对文件指纹；写回后清掉 `renames` 中已应用的记录。

## 7. 界面

- 活动栏"模型"面板：最近的模型；模型 → schema → 表（有错的标红）；工具栏：打开、新建、从库反向生成、重新加载；右键：新建表、用设计器打开、改名、删除、与库比对。
- "比对"标签（新标签类型）：上方两边的选择（模型或连接，再选 schema）、交换、选项；中间三层结果树（勾选框、只看差异、按状态过滤、疑似改名的"按改名处理"）；右侧选中项的两边定义对照，差异标色；底部"同步到目标"（数据库：脚本预览确认框，沿用 M3 保存确认框；模型：直接写回）、复制脚本、在查询标签中打开、另存为。
- 设计器：目标是模型时标题为"模型名 / schema.表"，保存不弹确认框。
- 入口：对象树 schema 右键"与模型比对…""另存为模型…"；标题栏"文件"菜单"打开模型""新建模型""比对…"。

## 8. 测试

- 方言：表配对（名字、记下的改名、推测的改名）；各选项；同步脚本顺序（快照）；`apply_changes` 与 `diff_table` 互逆（应用后再比对没有差异）。
- 服务层：模型目录读写（文件名转义、未知字段保留、坏文件、指纹冲突、改名记录）；反向生成任务；比对；同步执行；写回模型。YAML 写法用快照固定。
- 实库（12 个目标）：反向生成 → 在模型中改表（改名、加列、换索引、加外键）→ 与库比对 → 同步到库 → 再比对无差异；同一个库两个 schema 的库对库比对；写回模型。
- 前端：结果树、勾选和依赖提示的单元测试；浏览器实测完整流程。
