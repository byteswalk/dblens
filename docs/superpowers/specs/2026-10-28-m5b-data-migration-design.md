# M5b 数据迁移 设计

日期：2026-10-28。上级设计：总设计文档 `docs/superpowers/specs/2026-10-22-dblens-design.md` 第 11 节（M5 迁移）；
M5a 设计 `docs/superpowers/specs/2026-10-28-m5a-structure-migration-design.md`（迁移方案、两步脚本、迁移标签、迁移报告）；
M2b 设计 `docs/superpowers/specs/2026-10-27-m2b-import-design.md`（分批写入、出错停止或跳过）。

## 1. 目标与范围

在 M5a 的建表和建约束之间迁数据：分批读源、按目标列类型转换、写入目标；断点续传、进度；行数校验和可选的抽样逐值比对；
迁完把序列和自增推到当前值。

不做：
- 增量同步（迁移期间源库的写入）：界面提示迁移期间源库最好不要写入；
- 调用各库的批量装载工具（COPY、LOAD DATA、SQL*Loader 等）；
- 视图、例程等的数据（它们没有数据）。

## 2. 已定的决策（2026-10-28 与用户确认）

| 问题 | 结论 |
|---|---|
| 搬运方式 | 服务端流式分批：读源 → 按目标列的逻辑类型转换 → 参数化批量写入（M5a 时已定） |
| 断点续传 | 迁移记录存在程序数据目录（方案快照 + 进度），每批提交后更新；迁移标签中列出未完成的迁移，可继续或放弃；另存的方案仍是普通 JSON |
| 单行出错 | 可选：停止（默认）/ 跳过并记录（与 M2b 导入一致） |
| 并行 | 可设并行表数 1–4，默认 2 |
| 数据范围 | 每张表可填源库写法的过滤条件（WHERE），可勾"只迁结构" |
| 校验 | 行数必做；可选按主键抽样逐值比对 |

## 3. 流程

### 3.1 模式与同名表

- 模式：结构和数据（默认）/ 只迁结构（即 M5a）/ 只迁数据（目标表必须已存在）。
- 同名表的处理方式：跳过、删除重建、只建缺的索引和约束（M5a），加上追加数据、清空后导入（`DELETE FROM`，与 M2b 一致不用 TRUNCATE）。

### 3.2 步骤

一个任务依次：

1. 建序列、（删表）、建表（M5a 第一步）；
2. 迁数据：按表并行（并行表数 1–4）；
3. 建索引和约束（M5a 第二步）；
4. 序列和自增推到当前值；
5. 校验。

某张表建表失败或迁数据失败时，依赖它的语句跳过（同 M5a），其余照常。

### 3.3 迁移记录与续传

- 开始时在数据目录建 `migrations/<id>.json`：方案快照、当前步骤、已执行的语句（序号）、每张表的状态（等待 / 迁移中 / 完成 / 失败 / 只迁结构）、
  已提交的行数、跳过的行数、最后提交的主键值、出错信息；每批提交后更新（先写临时文件再改名）。
- 任务取消、出错、程序关闭后记录保留。完成（含校验）后标记为完成，不再列为未完成。
- 继续：重新连接两端、确认表还在；已执行的语句和完成的表跳过；迁移中的表从最后提交的主键之后读；没有主键的表先清空目标表再从头迁（提示）。
- 放弃：删除记录（不动目标库）。

## 4. 数据的读、转换、写

- 读：每张表一个源库连接，一条流式查询 `SELECT 迁移的列 FROM 表 [WHERE (过滤条件) AND (主键 > 上次的位置)] ORDER BY 主键`；
  复合主键写成 `(a > ?) OR (a = ? AND b > ?)`；大字段读完整值（单个上限 256 MB，同导出）；没有主键的表不排序。
- 转换：按目标列的逻辑类型转换，复用并扩充 M2b 的转换（布尔与 0/1、UUID / JSON / 时间间隔转文本、带时区时间戳转本地时间、二进制等）；转换失败算该行出错。
- 写：每张表一个目标库连接，参数化的多行 INSERT（每条至多 500 行），每批（默认 1000 行，100–100000）一个事务，提交后更新记录；
  生成列不写；自增列按原值写（达梦先 `SET IDENTITY_INSERT 表 ON`）。
- 出错：停止——这张表停在出错的批之前，标为失败（其余表照常），修改后可续传；跳过——出错的批逐行重试，失败的行（主键和错误）写进报告（至多 1000 行，超出只计数）。
- 进度：每张表已迁行数 / 估计总行数（元数据的行数估计，没有时只显示已迁行数）。

## 5. 序列与自增、校验

- 自增：按目标表中该列的最大值加一调整——MySQL `ALTER TABLE … AUTO_INCREMENT = n`；PG 系标识列 `ALTER COLUMN … RESTART WITH n`、serial 用 `setval`；
  Oracle `ALTER TABLE … MODIFY … GENERATED BY DEFAULT AS IDENTITY (START WITH n)`；达梦写计划时实测确定，不支持时报告中提示。
- 序列：读源序列的当前值，目标上推到同样的位置——PG 系 `setval`；Oracle 18c 起 `ALTER SEQUENCE … RESTART START WITH n`，更早删掉重建；达梦实测确定。
- 校验：每张表比对行数（源按过滤条件计数）；可选抽样（默认关，每表 100 行，按主键取最前和最后各一半）逐值比对，
  两边按目标列的逻辑类型规整后比较（小数去掉末尾的 0、时间按目标精度截断、CHAR 的末尾空格）；不一致的列列出。
- 迁移报告：在 M5a 的报告上加每张表的行数（源 / 目标 / 跳过）、用时、校验结果、跳过的行、序列和自增的调整。

## 6. 界面

- 迁移标签工具栏：模式、每批行数、并行表数、出错时（停止 / 跳过并记录）、抽样校验的行数（0 为不抽样）。
- 映射区每张表：过滤条件输入框、"只迁结构"勾选。
- 同名表的处理方式加"追加数据""清空后导入"。
- 执行中：当前步骤；按表列出状态、已迁行数 / 估计、用时；"取消"即暂停（记录保留，可继续）。
- 完成后：每张表的行数和校验结果、迁移报告。
- 标签顶部：未完成的迁移（源 → 目标、开始时间、进度），"继续""放弃"。
- 提示：迁移期间源库最好不要写入。

## 7. 接口

- 迁移方案加 `mode`（`all` / `structure` / `data`）、`data`（`batch_size`、`parallel`、`on_error`、`sample`），表的覆盖加 `filter`、`structure_only`；
  `existing` 加 `append`、`replace`。
- `GET /migrations`：未完成的迁移；`POST /migrations/{id}/resume`：继续（返回任务 id）；`DELETE /migrations/{id}`：放弃。
- 其余沿用 M5a（`/migrations/preview`、`/migrations`）。任务 `kind` 仍为 `migrate`，状态中加每张表的进度和当前步骤。

## 8. 测试

- 单元：增量读取的 SQL（单列、复合主键、过滤条件，各方言）、值转换、校验的规整、迁移记录的读写和续传位置。
- 服务：假驱动测分批提交与记录更新、停止与跳过、取消后续传、并行。
- 实库（串行）：测试结构中放多种类型的数据（中文、NULL、大字段、小数、时间、布尔、二进制），每个源库迁到 MySQL、PG、Oracle、达梦，核对行数和全部的值；
  续传（大表迁到一半取消再继续，无重复无遗漏）；跳过（有超长值的表，跳过的行被记下）；自增和序列推进后插入新行不冲突。
- 前端：方案的新选项、未完成迁移的列表、表的进度显示。
- 第一个任务照例是依赖复查。
